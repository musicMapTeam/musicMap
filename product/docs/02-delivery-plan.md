# 初赛交付、部署与材料定稿

版本：1.3 · 2026-09-27，对应应用 MVP 0.3.0。此文只保留初赛交付决定。官方依据来自 9 月 26 日[本地留档](../../references/official/2026-09-26/README.md)，本轮没有重新联网核对；档案是可见原文与截图，不是成功导出的原始 XLSX。

视觉优先级：用户将优秀视觉包装视为本项目的核心成功标准。网页、封面和视频采用 **动态排版主导的当代音乐节视觉**，波纹 / 干涉图形作辅助，现场照片与纸张承载卡片。方向已落到主要页面，详见[产品方案第 6 节](01-product-plan.md)。独立会话实操已有历史记录，视频与封面已有产物；0.3.0 的检查结果与当前材料版本分别见[任务记录](../../docs/PROJECT_STATUS.md)和[交付清单](../../delivery/README.md)。

## 1. 先回答工程量问题

| 问题 | 本项目决定 |
|---|---|
| 要先买服务器吗？ | 本轮不购买。先完成本地整合；真实联网部署需具备 Node.js 24 与持久磁盘的运行环境，最终托管尚未选定。 |
| 官方要求完整前后端吗？ | 已留档规则未将完整前后端列为初赛统一要求；本项目为了独立会话真实同意，主动实现最小服务端。 |
| Space 社交怎么演示？ | MVP 0.3.0 主入口为真实会话房间，另提供明确标注的本地双角色情景演示；两者新交换接受后均自动保存双方记录。 |
| 真正两台手机换卡需要什么？ | 两台设备访问同一 Node 服务，各持匿名凭据；服务使用 SQLite 共享状态并校验操作权限。公网访问还需 HTTPS 和持久磁盘。 |
| 要下载模型吗？ | 不需要。上一轮只查模型卡，未下载权重；模型选型已从现行方案移除。 |
| 必须放音频吗？ | 官方没有统一强制要求。Space 的卡片交换可先无音频；若做试听，则接真实可用素材并如实说明。 |
| 能用 WorkBuddy 交付吗？ | 单 HTML 可作为静态情景演示产物；其静态发布不运行本项目的 Node 后端。真实联网另按第 3 节部署。 |

“无须完整前后端”不等于只交一张效果图。我们的初赛目标是一份评委能打开、能操作、能看懂现场交换价值的在线交互 Demo。

## 3. 两种交付产物与访问范围

### A. 单 HTML：保留本地情景演示

WorkBuddy 官方有“分享 → 发布 → 发布为网站”功能，可把本地 HTML 发布成 `https://workbuddy.link/p/{页面ID}`。拿到链接的人可访问；关闭发布开关后停止访问。这是发布地址，不是本机预览。[WorkBuddy 轻量发布说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library/Lightweight-Publish)

`npm run build` 生成单一 `dist/index.html`，脚本、样式与预置图片内嵌，可交给 WorkBuddy 等兼容单 HTML 的入口展示。本地情景演示在一个浏览器切换示例角色，新交换接受后自动为双方各保存一份；旧版已接受但未保存的交换保留手动保存。相同两卡版本可打开已有双联，不重复申请；自己的卡仍可单独收藏。记录在 localStorage 中，Map 探索与票根导出也可在静态版操作。

**静态托管只运行前端。** 本项目联网模式请求同源 `/api/live`；只有 HTML、没有对应 Node 服务时，应显示服务未连接，并引导体验情景演示。它不能靠静态网页实现跨设备共享，也不能把单 HTML 发布成功记为后端上线。WorkBuddy 实际发布及兼容性尚未验证。

已有 WorkBuddy 说明不构成对当前账号额度、有效期和兼容性的保证。最终要确认实际访问方式；未经处理的公开分享链接也不等于定向内测，发布范围需遵循下述赛事口径。

### B. Node 服务：MVP 0.3.0 真实联网交付

采用已实现的 **Vite 原生 JavaScript + Node.js 24 内置 SQLite**，没有运行时 npm 依赖。构建后由 `server/index.js` 同时提供 `dist/` 和 `/api/live`，默认监听 `127.0.0.1:8787`。匿名身份、6 位房间码、成员、两卡快照、同意状态和双方私有记录存入 SQLite；前端短轮询同步。

真实联网只使用 `stage` / `crowd` 两张预置图片的引用，不上传个人照片。接收者接受后，服务在同一事务中自动保存双方各自的纪念记录；票根 PNG 由浏览器导出，不另建云文件存储。后端源代码与 Dockerfile 已具备，部署命令见[实施规格](03-build-guide.md)。

0.3.0 改善初次使用：空墙区分未入场与未展示，私卡保存后可主动展示或继续私藏；离开时可复制邀请码，入场栏保留重入码但不自动加入。票根界面与下载使用一致的交换完成时间。两种模式都写清数据归属，不因自动保存而宣称本地角色已变成真实多人。

部署采用单实例 Node、持续保留的磁盘或 Docker volume，前置反向代理提供 HTTPS。数据库目录不放入 Git、镜像或公开静态目录；更新应用时保留同一数据卷。不使用临时文件系统托管 SQLite，也不把多个实例各自的本地库当成共享数据库。当前没有选定线上主机、购买服务或执行部署。

### 评审访问与“未上线”口径

FAQ Q10 将任何人可访问、体验的公开平台发布视为上线，团队内部 / 定向小范围内测不计；提交指引 B9 又要求评审可直接访问的在线链接。当前安排是先内部运行与定向演示，再落实评委实际可用的访问方式，不提前做公开发行。房间邀请码只限制房内数据，不能替代站点访问控制；需要限制整个站点时在部署入口配置访问门槛，并向评委提供必要说明。最终提交方式以官方入口及答疑为准，不把团队处理方式写成官方保证。[FAQ 留档 Q4、Q8、Q10](../../references/official/2026-09-26/spreadsheet/06-faq-cells.md)

## 4. 音频与素材怎么处理

### 音频是否需要

- Space 可以用歌曲名称、现场环节、照片和感受表达共同记忆，双向交换不依赖音乐播放。
- Map 的试听是有益增强；若当前没有真实音源，保留作品和合作说明，并将试听写清未接入或暂不展示按钮。
- 演示视频可以有清楚的人声讲解，不要求必须用商业歌曲作背景音乐。
- 不为了制作初赛 Demo 先下载整库、爬平台音频或部署模型。少量适合演示的素材足够。

### 官方提供了什么

FAQ Q11 给出[赛事演示音乐歌单](https://c6.y.qq.com/base/fcgi-bin/u?__=UFgdsOYo9Glo)，限定赛事期间、非商业、仅评审演示，不允许用这些素材对外发布上线或赛后继续对外上线。初赛没有官方 API 或额外模型额度。[官方 FAQ Q6、Q7、Q11](https://saas.docs.qq.com/sheet/DR2VHa0JGT3ZGVFNKTmpybUdJ?tab=000006)

上次打开歌单时出现 QQ / 微信登录，未取得可用于网页的音频文件或嵌入方式。歌单入口与实际音源分开处理。WorkBuddy 的公开链接不会自动改变素材允许范围；若要使用官方歌曲，先落实如何供应与如何用于评审 Demo。无需音频的交互版可以先做，不因这个问题停工。

### 初赛最少素材

当前使用一场虚构活动、两张 AI 生成现场图、少量示例歌曲 / 环节标签及虚构音乐关系，页面明确说明。真实联网中的参与者为独立会话，不等于真实活动观众；真实音频和合作数据尚未接入。图片生成与图标来源见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)，相关来源见[资源台账](../data/resource-register.json)。

## 5. AI 怎样表述

根据实际制作过程，说明使用 Codex、WorkBuddy 等 AI 工具完成了哪些方案、界面或代码工作，以及团队如何筛选、修改和验证。未实际使用的工具不列入完成记录。

固定模板制卡、规则匹配与图查询不写成模型推理。当前不部署推荐模型，不下载权重，不付费调用推理 API。若未来发现明确的 AI 用户价值，另作小范围验证；它不再是本次交付前置条件。

## 6. 报名介绍与 2 分钟视频

报名介绍、现场演示脚本和提交核对集中在[参赛材料](../../docs/competition/README.md)。介绍按 100—300 字准备，现场演示脚本约 2 分钟。视频已有成片，以实际页面截图与票根编排，中文字幕、静音，并标注本地情景与独立房间；当前时长、体积、版本与镜头来源以[交付清单](../../delivery/README.md)为准，不把截图编排说成连续录屏。

封面为 16:9，以实际票根为主体，用“从一首歌，到同场的人”串起音乐探索与现场社交；Map 实际界面在视频中展示。成片、封面、可重渲染源文件及版本对应关系见交付清单；未变化镜头可复用已有真实截图并注明来源，不宣称全部重拍。0.3.0 介绍与演示须反映新本地交换自动保存、回原探索与新开路线的区别；材料完成与赛事正式提交分别记录。

## 7. 提交前只检查这些

- 评审地址实际可访问，必要的定向访问说明齐全，核心按钮与图片可用；评审期间保持可用。
- Demo、视频、介绍对“情景演示 / 真实双端 / 音频是否可用”的描述一致。
- 交换对象、共同点、双方同意和结果清楚；无需讲解按钮位置就能操作。
- 介绍 100—300 字；视频 ≤3 分钟、≤500M；封面 1 张、16:9；队伍信息填写完整。
- 按实际使用列第三方代码 / 素材与 AI 工具；已有部分和赛期新增部分分开，团队核对官网权属与提交条款。
- 10 月 8 日备齐材料，10 月 9 日实际上传并确认提交成功。
