## 3. WorkBuddy 可以怎么交付

### 路线 A：轻量发布，优先用于前端演示

WorkBuddy 官方有“分享 → 发布 → 发布为网站”功能，可把本地 HTML 发布成 `https://workbuddy.link/p/{页面ID}`。拿到链接的人可访问；关闭发布开关后停止访问。这是发布地址，不是本机预览。[WorkBuddy 轻量发布说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library/Lightweight-Publish)

当前已实现前端交互 Demo，`npm run build` 生成 `dist/index.html`，将脚本、样式和图片嵌入单文件，作为轻量发布的输入。尚未在 WorkBuddy 实际发布；发布后确认图片、交互和本地存储均可用。轻量发布提供网页访问，不承担本项目的跨设备共享状态。

官方这篇说明未明确给出免费额度、固定有效期、休眠策略或任意多文件项目的兼容保证。当前尚未操作用户账号的发布入口，不能承诺已经能用或永久有效。最终用外部手机检查访问和资源，再把真实链接填入报名表。

### 路线 B：WorkBuddy + CloudBase，适合多文件应用或共享服务

CloudBase 官方教程支持由 WorkBuddy 调用连接器或 `/cloudbase` 构建、部署 React / Vite 等应用，返回公开访问链接；也支持上传已经构建好的 HTML / CSS / JS。[WorkBuddy 部署教程](https://docs.cloudbase.net/en/ai/cloudbase-ai-toolkit/tutorials/workbuddy-quickstart)、[CloudBase 托管快速开始](https://docs.cloudbase.net/hosting/quick-start)

当轻量发布不能完整承载产物，或决定加入两台设备真实换卡时，采用这条路线。网页托管、数据库和云函数按需要使用；发布静态网页本身不要求数据库。官方已有通过 WorkBuddy 创建双人房间与共享数据应用的示例，可作实现参考。[双人应用官方案例](https://docs.cloudbase.net/en/ai/cloudbase-ai-toolkit/tutorials/workbuddy-chess-app)

CloudBase 通常需要腾讯云账号实名认证、环境创建与登录授权。免费体验有资格、额度和有效期条件，用户当前账号状态尚未核实；不在本次方案中购买套餐。默认域名可能有访问提示页，最终返回链接必须实际检查，不能把平台子域名当成已备案的独立域名。[前置条件](https://docs.cloudbase.net/hosting/quick-start)、[费用与体验条件](https://cloud.tencent.com/document/product/876/127357)、[默认域名说明](https://docs.cloudbase.net/service/alias)

### 本轮决定

**前端主流程已经落地，接下来选择能稳定承载它的发布入口。** WorkBuddy 是可采用的发布工具；能否交付取决于最终链接和真实功能。当前没有登录、创建云环境、购买服务或发布网页。

## 4. 音频与素材怎么处理

### 音频是否需要

- Space 可以用歌曲名称、现场环节、照片和感受表达共同记忆，双向交换不依赖音乐播放。
- Map 的试听是有益增强；若当前没有真实音源，保留作品和合作说明，并将试听写清未接入或暂不展示按钮。
- 演示视频可以有清楚的人声讲解，不要求必须用商业歌曲作背景音乐。
- 不为了制作初赛 Demo 先下载整库、爬平台音频或部署模型。少量适合演示的素材足够。

### 官方提供了什么

FAQ Q11 给出[赛事演示音乐歌单](https://c6.y.qq.com/base/fcgi-bin/u?__=UFgdsOYo9Glo)，限定赛事期间、非商业、仅评审演示，不允许用这些素材对外发布上线或赛后继续对外上线。初赛没有官方 API 或额外模型额度。[官方 FAQ Q6、Q7、Q11](https://saas.docs.qq.com/sheet/DR2VHa0JGT3ZGVFNKTmpybUdJ?tab=000006)

上次打开歌单时出现 QQ / 微信登录，未取得可用于网页的音频文件或嵌入方式。歌单入口与实际音源分开处理。WorkBuddy 的公开链接不会自动改变素材允许范围；若要使用官方歌曲，先落实如何供应与如何用于评审 Demo。无需音频的交互版可以先做，不因这个问题停工。

### 初赛最少素材

一场活动资料或明确的示例场次；两张自有 / 允许使用的照片；两位示例参与者；少量歌曲 / 环节标签；一组有出处的音乐关系；短句与卡面。当前资料登记见[资源台账](../data/resource-register.json)。

## 5. AI 怎样表述

根据实际制作过程，说明使用 Codex、WorkBuddy 等 AI 工具完成了哪些方案、界面或代码工作，以及团队如何筛选、修改和验证。未实际使用的工具不列入完成记录。

固定模板制卡、规则匹配与图查询不写成模型推理。当前不部署推荐模型，不下载权重，不付费调用推理 API。若未来发现明确的 AI 用户价值，另作小范围验证；它不再是本次交付前置条件。

## 6. 作品介绍工作稿

下文按 100—300 字准备，最终按实际完成范围调整：

> Music Map 将音乐关系探索与现场社交连接起来。用户从喜欢的艺人出发，沿有作品依据的关系发现新声音，再进入关联演出的 Music Space。在同一场现场，每个人可以用一张照片、一首歌或一个环节和一句感受制作现场卡，因共同的音乐时刻看见彼此。双方选择自己的卡并确认后，交换不同视角，留下共同记忆，也可从卡中的音乐继续探索。我们希望把“听过同一首歌、在过同一场现场”变成自然的交流理由。初赛通过可交互网页展示这一流程，并如实标注示例数据与演示范围。

若最后是本地角色版，保留演示范围说明；若完成真实双端，写明并展示实际能力。已有原型与赛期新增分别记录，不代填“从未上线”。

## 7. 视频脚本：目标 2 分 40 秒

| 时间 | 屏幕动作 | 要讲清的价值 |
|---|---|---|
| 0:00—0:20 | 现场照片、产品一句话 | 同一场演出留下不同视角，人需要自然的开口理由 |
| 0:20—0:45 | Map 选艺人、看一条真实 / 标明示例的关系、进入 Space | 音乐探索如何衔接现场；无需铺陈所有功能 |
| 0:45—1:15 | A 选照片、歌曲 / 环节、写话，生成现场卡 | 卡片是具体记忆，自己先获得价值 |
| 1:15—1:50 | B 看见共同点、选择自己的卡并申请，A 接受 | 明确两张卡、双方同意；本地角色切换要可见标注 |
| 1:50—2:15 | 两张卡形成双联记忆、保存、从音乐再探索 | 社交结果与音乐发现形成连续体验 |
| 2:15—2:30 | 原有挑战或另一条关系，快速展示 | 保留 Map 的轻探索与参与感 |
| 2:30—2:40 | 实际完成范围、试用发现（若已有）、收尾 | 只陈述已经完成和观察到的结果 |

封面用一张 16:9 图，重点展示 **Map 的关系 + 两张现场卡的交换结果**。当前旧原型截图不冒充新版现场社交画面。录制时长与体积按官方上限留余量。
