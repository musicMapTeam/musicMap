## 3. 两种交付产物与访问范围

### A. 单 HTML：保留本地情景演示

WorkBuddy 官方有“分享 → 发布 → 发布为网站”功能，可把本地 HTML 发布成 `https://workbuddy.link/p/{页面ID}`。拿到链接的人可访问；关闭发布开关后停止访问。这是发布地址，不是本机预览。[WorkBuddy 轻量发布说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library/Lightweight-Publish)

`npm run build` 生成单一 `dist/index.html`，脚本、样式与预置图片内嵌，可交给 WorkBuddy 等兼容单 HTML 的入口展示。首页「体验示例」进入本地情景，在一个浏览器切换示例角色；新交换接受后自动为双方各保存一份，旧版已接受但未保存的交换保留手动保存。相同两卡版本可打开已有双联，不重复申请；自己的卡仍可单独收藏。记录在 localStorage 中，Map、独立音乐收藏与票根导出也可在静态版操作。

0.15 单 HTML 的范围包括：樱下放映 · 夜场全屏小院、首屏价值主张、按纸件占位取景、寻声一局与完整图鉴、本地卡操作与双联仪式页、逐人署名、120 首开放曲库和本机音乐收藏；单卡与双联夜场票根 PNG 提供成品预览。WebGL 不可用时，寻声保留同一布局与可见性的二维图，页面回到浅纸深字。Three 0.186.1、MIT 渲染模块与 GSAP 3.15.0 / Flip 随前端打包，不依赖外部场景、HF 请求或模型服务；完整 CSV 留在本地。真实主页、跨场次现场收藏及新建场次仍需同源服务。文件分享只在浏览器支持时显示，并由用户点击；下载与长按保存保留。构建和目标托管表现按本轮实际结果记录。

**静态托管只运行前端。** 本项目联网模式请求同源 `/api/live`；只有 HTML、没有对应 Node 服务时，应显示服务未连接，并引导体验情景演示。它不能靠静态网页实现跨设备共享，也不能把单 HTML 发布成功记为后端上线。WorkBuddy 实际发布及兼容性尚未验证。

已有 WorkBuddy 说明不构成对当前账号额度、有效期和兼容性的保证。最终要确认实际访问方式；未经处理的公开分享链接也不等于定向内测，发布范围需遵循下述赛事口径。

### B. Node 服务：真实同场与个人收藏

0.9 新增受身份保护的个人收藏读取与本人双联删除接口，不修改数据库结构。`GET /api/live/library` 汇总本人跨场次卡片和双联，离场后仍可读；返回已离开的场次须主动加入。三维照片沿用既有授权读取，不生成公开地址；撤权、离场和释放缓存前先撤下场景内容。

沿用 **Vite 原生 JavaScript + Node.js 24 内置 SQLite**，后端没有 npm 运行时依赖；浏览器打包 `qrcode-generator`、Three 0.186.1 与 OverlayScrollbars 2.16.0，分别用于二维码、主题场景与页面滚动条。构建后由 `server/index.js` 同时提供 `dist/` 和 `/api/live`，默认监听 `127.0.0.1:8787`。匿名身份、6 位房间码、自定义活动、成员、照片、两卡快照、同意状态和双方私有记录存入 SQLite；前端短轮询同步元数据。单一樱花视觉不改动这些业务数据。

0.4.0 允许用户填写自己的活动，上传经浏览器重绘压缩的 JPEG，并选择舞台 / 人海 / 同伴 / 细节视角。图片存在 SQLite BLOB，不写入公共静态目录；读取须携带匿名身份并满足本人、当前展示卡、交换或个人记录的权限。接收者接受后，服务在同一事务中自动保存双方各自的纪念记录，照片与文字引用保持发出时快照。0.4 历史实操已下载 **1600×1800** 的单卡 **1,041,477 B** 和双联 **1,097,920 B** PNG，并目视查看相关票面；不作为 0.5 新主题票面的检查结果。

删除本人纪念记录不影响对方副本，也不撤销 accepted 交换的照片读取依据；不要将它描述成彻底删除已分享照片。旧库通过增列兼容，0.4 重启迁移后原森森 / 小舟身份与旧房间列表仍可读回，既有虚构房间与快照保留示例语义。后端源代码与 Dockerfile 已具备，接口边界、运行和部署命令见[实施规格](03-build-guide.md)。

联网新卡先选照片，再选视角和留一句；旧卡直接进入第二步，环节和歌名收在「更多细节」。同一表单保留输入，私藏／展示明确。同页关闭再开保留未保存草稿；保存成功或换房清理，刷新和切页不承诺恢复。保存后按房间状态提供邀请、看同场卡片或展示，并可预览导出、进入收藏。离场保留自己的卡和双联，重入只预填邀请码，由用户主动加入。首页提供邀请码入口，在入场页填写并确认加入；邀请时没有当前房间则先留昵称、创建场次，再展示邀请。双联空态提供回到已有现场的入口；失效身份提供重新入场，并说明新身份无法带回旧记录。

部署采用单实例 Node、持续保留的磁盘或 Docker volume，前置反向代理提供 HTTPS。数据库目录不放入 Git、镜像或公开静态目录；更新应用时保留同一数据卷。不使用临时文件系统托管 SQLite，也不把多个实例各自的本地库当成共享数据库。当前没有选定线上主机、购买服务或执行部署。

### 评审访问与“未上线”口径

FAQ Q10 将任何人可访问、体验的公开平台发布视为上线，团队内部 / 定向小范围内测不计；提交指引 B9 又要求评审可直接访问的在线链接。当前安排是先内部运行与定向演示，再落实评委实际可用的访问方式，不提前做公开发行。房间邀请码只限制房内数据，不能替代站点访问控制；需要限制整个站点时在部署入口配置访问门槛，并向评委提供必要说明。最终提交方式以官方入口及答疑为准，不把团队处理方式写成官方保证。[FAQ 留档 Q4、Q8、Q10](../../references/official/2026-09-26/spreadsheet/06-faq-cells.md)

## 4. 音频与素材怎么处理

### 音频是否需要

- Space 可以用歌曲名称、现场环节、照片和感受表达共同记忆，双向交换不依赖音乐播放。
- Map 当前提供真实作品、逐人制作署名与来源；试听链接已撤下，QQ 音乐同版本直达尚未核实，没有内置试听。
- 演示视频可以有清楚的人声讲解，不要求必须用商业歌曲作背景音乐。
- 已下载完整 HF 元数据 CSV；前端内置 120 首整理后的共同署名作品，不下载平台音频或部署模型。

### 官方提供了什么

FAQ Q11 给出[赛事演示音乐歌单](https://c6.y.qq.com/base/fcgi-bin/u?__=UFgdsOYo9Glo)，限定赛事期间、非商业、仅评审演示，不允许用这些素材对外发布上线或赛后继续对外上线。初赛没有官方 API 或额外模型额度。[官方 FAQ Q6、Q7、Q11](https://saas.docs.qq.com/sheet/DR2VHa0JGT3ZGVFNKTmpybUdJ?tab=000006)

上次打开歌单时出现 QQ / 微信登录，未取得可用于网页的音频文件或嵌入方式。歌单入口与实际音源分开处理。WorkBuddy 的公开链接不会自动改变素材允许范围；若要使用官方歌曲，先落实如何供应与如何用于评审 Demo。无需音频的交互版可以先做，不因这个问题停工。

### 初赛最少素材

当前精选含 **12 位艺人、13 份合作录音、13 条共同演唱边与 2 个独立回路**，逐人制作署名保留具体来源。新增《黑暗骑士》、2020 双 J 联唱现场与《Stay With You》英文版，版本限定和依据见[关系网记录](../../references/research/2026-09-27/vocal-network-expansion.md)。不内置音频，不将真实艺人绑定虚构活动。另从完整下载的 HF 元数据中整理 120 首作品供独立搜索，共同署名不当作已核实制作工种或合唱边。完整 CSV 共 114,000 行、20,118,244 B，固定版本与下载命令见[下载记录](../../references/research/2026-09-27/huggingface-download.md)，不随网页或运行包分发。

虚构关系、活动与两张 AI 生成现场图独立作为示例并兼容旧记录。用户自建活动、共同歌名和到场视角为自述内容，不代表平台核验。真实房间支持用户照片，照片与数据库不进入源码仓库或公开材料。0.4 录制将项目的两张 AI 图片经真实文件选择器上传并压缩至 960px，用于证明上传流程，不能描述成真实现场摄影或用户反馈。图片生成与图标来源见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)，当前逐人依据见[合作署名记录](../../references/research/2026-09-27/collaboration-roles.md)，原 0.4 来源保留在[真实合作登记](../../references/research/2026-09-27/real-catalogue-sources.md)。
