## 1. 定位与目标用户

**Music Map：从喜欢，走向未知。** 从一位喜欢的华语歌手出发，沿着每一条都有真实录音依据的合唱，走到下一位、找到下一首，把路线和歌留下，再把一道不剧透的题发给朋友。

定位沿用产品负责人的原话：

- PRD v0.2 §1.1：「面向年轻、重度使用 QQ 音乐、关注艺人且愿意探索的听众，以具有空间感的艺人关系网，让用户从熟悉的华语流行艺人出发，发现相关艺人和音乐，并留下探索结果。」
- 参赛工作稿 07 §1：「Music Map 面向关注艺人、愿意探索的年轻乐迷，回应“喜欢熟悉的歌手，却不知道如何发现相关新声音”的需求。」

本方案据此简写为：**面向年轻、关注艺人且愿意探索的华语乐迷。** 首批人群是重度使用 QQ 音乐的年轻听众，产品本身不连接 QQ 音乐账号。

使用时机（推断，未经试用）：听到一首喜欢的合唱，想顺着它找到下一位歌手；和朋友互相出题，比谁先找到两位歌手之间的路。

PRD §1.1 已写明，“用户因为关注熟悉艺人而愿意探索关联艺人”是产品假设。到 2026-09-29 仍未做目标用户试用，没有真实用户研究结论。

## 3. 规则

### 3.1 寻声（步数挑战的当前形式）

- **开局。** 进入唱片店默认发一局寻声，第一题是「费玉清 → 邓紫棋，隔着几首歌？」。「换一组」按固定顺序轮换 12 道预设题：原有 5 道，加上 2026-09-28 扩网后新增的 7 道（两端相隔 4–6 首）。目录中也可以「自选起点和终点」。开局前校验：起终点不能相同，不连通时先说明“本专题已收录的合作关系尚未连通”，不宣称现实中没有合作。
- **迷雾。** 桌上正面只显示起点、终点和已认识的歌手，其余唱片背面朝上。终点带「终点」签，但它的合作仍封着，不能从终点倒推。点背面唱片只提示“这张还盖着”。
- **翻开与前往。** 所在歌手的全部合作以手牌列出。未翻开时只显示歌名；翻开后才显示合唱者、版本与来源。只有沿已翻开的合作明确「前往」才算一步。翻开、提示、拖动、缩放、查看都不计步。
- **提示三级。** ①还隔几首，以及面前几首会更近；此后每次前往盖「近 / 远 / 平」章。②往哪翻：标出一首位于最短路线上的合作。③揭晓：确认后记为「已揭晓」，不算抵达，已翻开的唱片与用户路线保留。
- **返回。** 「退一步」（读屏：返回上一位并撤销一步）撤销一段；「回到起点」图标按钮先确认，已翻开的唱片保留。沿边走回旧歌手，算一次新的移动。
- **结束。** 到达终点是唯一的完成条件。抵达后整桌翻开、路线描金，再打开「连线歌单」：按顺序列出每首合唱、版本、来源与署名，以及有效步数、本专题最短、翻开首数、认识人数与提示次数。「留下这 N 首」把路线上的真实录音存入「留下的歌」。减少动态时不播放仪式，直接打开歌单。
- **“最短”只作对比。** “最短”只出现在提示、揭晓和连线歌单的「本专题最短」里，只指当前收录范围。用户走的路线不称最短。
- **泄题守卫。** 局中关闭搜索、关系面板与署名表（署名表会带出未认识的人名），到连线歌单再开放。页面文字、读屏文字、三维标签与二维降级图读同一可见集合。
- **保存。** 中途离开，保存目标、路径、已翻开的合作与提示，可以继续。已抵达或已揭晓的局只读。「我的发现」显示「寻声 · 进行中 / 已抵达 / 已揭晓」。

### 3.2 完整图鉴与自由漫游（PRD §4）

- **起点。** 首页搜索只覆盖本专题收录的歌手，名字和别名都能搜到，宽窄字符、大小写和标点不影响匹配。输入为空时显示 4 位示例歌手：周杰伦、林俊杰、邓紫棋、孙燕姿。搜不到时显示“本专题还没收录「…」，先从这几位出发试试”，不说该艺人不存在。同名歌手用稳定 ID 区分。
- **行走。** 在「完整图鉴」里，点当前歌手的相邻歌手，就沿两人之间的第一首合唱走过去；三维标签、二维图和搜索结果都能这样走。点不相邻的歌手只选中查看，并提示两人没有直接合唱。连线面板里的「前往」是显式的移动入口。
- **本次探索条。** 「返回上一位」「回到起点」「本次发现 · N 首」「结束探索」常驻。漫游的回到起点不弹确认，留下的歌保留。“当前路线”与“探索记录”分开存：退回会缩短路线，但保留分支。
- **结束与继续。** 「结束探索」把本条记录标为已结束，并打开回顾。已结束的漫游点歌手只选中；点「继续本次探索」后才能再走，再次结束仍更新同一条记录。
- **换起点。** 从首页选新歌手或点「从 TA 再出发」，都会新建漫游。当前漫游若已走过或留过歌，先确认“结束当前探索，并从某某开始新的探索？”。旧漫游标为已结束，留在「我的发现」。没有进度的漫游直接替换。
- **转成寻声。** 在图鉴里选中一位不相邻、但本专题能连通的歌手，出现「和 TA 隔几首？」，从当前位置开一局寻声。

### 3.3 本次发现与探索回顾（PRD §5）

- **留下。** 「留下」只给一句短提示，不打断探索。本次发现的 N 只计本次漫游主动留下的不同录音，不计浏览或收听次数。移除后可撤销，撤销恢复原位置；移除后再留下，排到末尾。按录音 ID 去重，同名不同版本分开计。
- **两份清单。** 真实录音留下后，同时进入本次漫游的清单和全局「留下的歌」。在漫游里移除，两处一起移除。在「留下的歌」里取消，只影响「留下的歌」，已有漫游的清单保持当时的记录。开放曲库的作品只进入「留下的歌」。
- **回顾顺序。** 按 PRD §5.3 排列：
  1. 概览：日期、起点、途经艺人数、留下首数，不按速度或步数排名。
  2. 留下的歌：默认展开，附发现来源，如“沿 A 与 B 的合作《X》留下”“在某某的作品里留下”。
  3. 我走过的路：可展开，按真实移动分段。
  4. 途经艺人：可展开，去重，每人带「从 TA 再出发」。
  5. 后续：「继续本次探索」「开始新探索」「回到小院」。
- **分支。** 走 A → B → C 后返回 B，再走 B → D，回顾显示“A → B → C”、“返回 B，换个方向”、“B → D”，不画 C → D。回到起点显示“返回起点，重新探索”。
- **空状态。** 没留歌时显示“这次还没有留下歌曲”；只在起点就结束时显示“还没有走到下一位”。
- **「我的发现」。** 分「探索记录」与「留下的歌」两栏。探索记录只列有进度的记录，按更新时间排序，可以回顾、继续或删除；删除前先确认。
- **只存本机。** 记录只存在当前浏览器，清除网站数据后无法找回。保存失败时显示提示和「重试保存」，页面内容保留。

### 3.4 分享：不剧透

- **只带题目。** 「出题给朋友」或「把这道题发给朋友」生成 `?from=<起点>&to=<终点>#/explore`。链接只带起点和终点。答案、用户路线、翻开的唱片、提示、收藏与历史都不带。
- **发送方式。** 浏览器有系统分享面板时用它；没有就复制到剪贴板；再不行就显示可选中的链接，让用户手动复制。连线歌单的「换个起点再出一题」可以出一道自己还没走过的题。
- **朋友打开。** 链接只读取一次，读后从地址栏移除，刷新不会重复发题。朋友得到同一局寻声，题签上方有「朋友出的题」和规则，可以收起。歌手不在本专题或两端不连通时，提示打不开的原因。同一道题再次打开，继续桌上已有的那一局。
- **战绩卡。** 仅限已抵达或已揭晓的局。PNG 为 1080×1350，只画起点、终点和背面朝上的中间站，写明步数与提示次数，二维码编码同一道题的链接，不写中间的歌手和歌名。
- **发现卡片**（PRD §5.8）。从漫游回顾生成，PNG 为 1080×1350。内容是起点、途经歌手（最多 6 位）与留下的歌（最多 5 首），超出时标「节选」。完整路线和来源仍在网页回顾里，卡片不代替它。
- **用户主动。** 两种图片都只在用户点击后于本机生成；预览中「下载图片」或「分享图片」（浏览器支持文件分享时才显示）都要再点一次。不自动发布，不上传任何内容。

### 3.5 数据与署名

- **边的依据。** 每条边对应一份具体录音：两人都被署名为演唱者，并有官方来源（唱片公司或艺人官网、用 oEmbed 核对的官方 MV、商店发行元数据）。共同作词、作曲、制作、编曲、和声、旁白、MV 出演都不建边；合辑同场、各自翻唱、同名歌曲也不算。
- **版本限定。** 现场版按特定录音登记，不把独唱原版改写成合唱。2 份现场只见官方影像（《后来的我们》《年少有为》），版本说明写“未见音频发行”；《爱我还是他》扩网登记时也只有影像，2026-09-29 在 QQ 音乐找到同场、无专辑的现场音轨，工作区版本改记为“QQ 音乐有同场现场音轨”（已部署的 `0b1eadc` 仍写“未见音频发行”），是否接受见 §9 第 12 条。
- **乐团与个人分开。** 五月天（`real-mayday`，乐团）只接整团署名的演唱；阿信（`real-ashin`）是本人。统一规则待产品负责人确认（见第 6 节）。
- **当前规模。** 29 位歌手、37 份录音、37 条边，全部连通，有 9 个独立回路，直径 6（目录版本 `real-vocal-2026-09-v4`）。“完整”只指当前精选，不是音乐百科。
- **核实流程。** 2026-09-28 新增的 24 条边经研究与独立复核两轮；原有 13 条按 2026-09-27 的来源登记核对，没有独立复核记录。HF 共同署名只作线索，不作证据。3 个候选经核对后未采用：《布拉格广场》《（……恋人絮语）》《（……小小牧羊人）》。
- **署名表。** 按人列出已核实的工种，来源精确到工种；未列出不表示未参与。
- **开放曲库。** 独立入口，126 首华语共同署名作品，只表示共同署名，不是合唱，也不进关系图。
- **虚构数据。** 「情景示例」是虚构数据，不出现在菜单中，只让 0.15 的旧记录还能打开，不与真实图谱混用。
- **排除名单。** 黄明志、吴亦凡、明日花綺羅不收录。这是一项产品决定（记录见[扩网记录](../../references/research/2026-09-28/network-expansion.md)“内容风险”），待产品负责人确认。

### 3.6 QQ 音乐同版本直达

用户 2026-09-29 决定：作品可以链接到 QQ 音乐，但**只链接同一录音、同一版本的歌曲页**。这一决定改变了 PRD v0.2「不外跳」的规则（§1.2、§3、§8.1），待产品负责人确认。

- 只用核实过的 `songmid`，拼成 `https://y.qq.com/n/ryqq/songDetail/{songmid}`。不猜 ID，不链接搜索页；没有同版本页面就不放入口，也不用其他版本或现场顶替。
- 核实结果：37 份录音中 31 份有同版本页。6 份没有：
  - 《黑暗骑士》：QQ 的演唱署名是五月天乐团，待确认五月天与阿信的节点规则。
  - 《稻香 / Stay With You》联唱、《给我一首歌的时间》超时代现场、《屋顶》、《后来的我们》现场、《年少有为》现场：QQ 上没有同一版本。
  - 逐条原因见[核对登记](../../references/research/2026-09-29/qq-music-links.md)。
- 入口文字是「去 QQ 音乐听」，挂在具体录音上，不挂在 MV 标签旁。它出现在作品条目、翻开后的手牌、连线歌单、署名面板和「留下的歌」里。「去 QQ 音乐听」和「留下」互不触发。
- 没有同版本的录音显示「QQ 音乐暂无同一版本」；《黑暗骑士》显示「QQ 音乐 · 同版本待确认」。连线歌单、署名面板和「留下的歌」里还会写出原因。
- QQ 自己的署名与本专题不同时，照实写出，如「QQ 音乐署名：周杰伦」。涉及《说好不哭》《等你下课》（歌手栏只有周杰伦）和《私奔到月球》（写五月天乐团）。边仍以已核实的逐轨演唱署名为准。
- 寻声局中不显示缺链原因，也不显示会点出未认识歌手的 QQ 署名，以免泄题。
- 点击后离开本应用。QQ 音乐可能要求登录、开通 VIP 或下载 App（如《过》未开通时只能试听片段）。这些情况只核对了元数据，没有在真机、中国大陆网络或登录账号下验证。
- 应用内不播放、不下载、不嵌入任何音频。核实时也没有请求音频地址。

### 3.7 与 PRD 不同的外跳：来源链接

作品来源与署名来源在界面上是外链，新标签页打开。PRD §7 的原意是资料来源链接“用于核验，不因此增加面向用户的外跳入口”。现状偏离了这一条，是否改为不可点的引用，待产品负责人确认。

## 4. 范围对照：PRD v0.2 与 0.16

| PRD v0.2 要求（§3） | 0.16 实现 | 差异与决定 |
| --- | --- | --- |

## 6. 艺术方向

「樱下放映 · 夜场」由用户在 0.15（2026-09-27）冻结，0.16 沿用。0.15 用户原话：“优秀的视觉包装是我们项目能否成功的根本”，“这个找关系的玩法应该是探索性的，不是把结果全贴出来给用户了”。

0.16 把小院讲成一家夜场唱片店：唱片柜台通向唱片店，唱片柜通向「我的发现」，舞台只作安静的聆听角落。照片墙、工作桌和交换仪式页已删除。细节见[视觉规范](../../docs/VISUAL_THEMES.md)。PRD v0.2 曾写“旧 HTML 外观不作为已认可方案”，视觉由产品负责人最终认可与否也在待确认之列。

## 7. 非目标

沿用 PRD v0.2 §3：地域模式、排行榜、限时竞速、强制社交、全曲库搜索、自训练推荐模型、账号与跨设备同步、QQ 音乐账号接入、平台歌单、独立艺人主页。

本轮另外不做：

- 内置音频、抓取或转存音频，以及非同版本的“去听”链接。
- 模型推理与 AI 匹配分数。
- 服务端与用户上传。
- Space 的现场卡、房间与交换。
