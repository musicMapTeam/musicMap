## 当前应用与历史参考

前端在 [`web/`](../web/)，服务在 [`server/`](../server/)。桌面使用悬浮左导轨，手机使用底部导航。Space 首页呈现可切换视角的照片卡叠：「做一张卡」进入本地示例制卡，「邀请朋友」进入真实房间；点选照片卡也可进入本地换卡。

- **沿着作品认识艺人**：11 位艺人、10 首作品、10 条有来源的共同演唱关系，提供官方 MV 外链；唱片节点、短作品浮卡和底部路线承载探索与挑战，来源按需打开。虚构示例独立保留并兼容旧记录，真实艺人不绑定虚构活动。
- **交换自己的现场视角**：自建活动、6 位邀请码与二维码、独立匿名会话；上传压缩照片并标记舞台 / 人海 / 同伴 / 细节，默认私藏，可主动展示。对方接受指定两卡的交换后，双方各留一份当时的快照。0.4 历史实操已下载自己的单卡和双方双联 PNG。
- **保留可离线体验的情景演示**：同一浏览器切换两个示例角色，新交换接受后自动为双方保存；自己的卡可单独收藏。旧版已接受但未保存的交换可手动保存，相同两卡版本打开已有双联。记录仅在本机，单 HTML 可用于兼容的静态入口，不提供共享后端。
- **为同一段记忆选择外观**：右上角主题按钮切换默认的声浪现场 `festival`、樱下放映 `sakura`、独立刊物 `zine`。三套方向覆盖页面与单卡 / 双联 PNG；樱下放映的原创小音乐街角采用 Sakura Crossing 的 MIT cel、深度描线、调色与 FXAA 源码，适配 Three 0.186.1。选择独立保存，切换不重置路线、身份、草稿或交换。完整规则见[视觉主题规范](../docs/VISUAL_THEMES.md)。

真实房间需要同源 **Node.js 24 + 持久化 SQLite** 服务，可用 Docker 部署。照片存于 SQLite BLOB，通过身份和共享关系授权读取，不放入公共图片目录。删除本人记录不会删除对方副本，也不撤销已接受交换的照片读取依据。匿名身份没有账号找回；用户填写的活动和共同歌曲不代表到场认证或音频授权。

房间使用卡片工作区，记录按个人收藏浏览；外观选择保留简短选项。页面采用 OverlayScrollbars 2.16.0 的自动隐藏 6px 浮动条，弹窗使用原生细滚动条。私藏／展示、双方同意、作品来源与 AI 示例图标记保留。

0.6 的构建、画面、打包与同步状态由[项目状态](../docs/PROJECT_STATUS.md)登记。0.5.1 的界面精简、0.5.0 的主题与 PNG，以及 0.4.0 的独立身份交换、上传和导出，均保留为历史证据。
