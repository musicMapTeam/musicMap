# 0.4 竞争力复盘与决策

2026-09-27。起点为已交付的0.3.0。用户要求根据比赛、竞品和开源代码重新审视idea，允许调整产品边界；本次不沿用上一轮的范围冻结。

## 本轮最重要的结论

视觉与流程完成度已有基础，最缺的是用户输入的真实性，以及“为什么值得交换”的具体理由。固定虚构艺人与两张预置照片不能证明音乐发现和现场记忆的用户价值。

比赛主叙事收紧为 **“同一刻，另一面”**：散场后，用另一位观众的视角补完整自己记住的那一刻。Space 是核心展示，Map 是有独立音乐收获的可选入口，不要求用户依次走完两个模块。

## 从短板到0.4改动

| 0.3短板 | 0.4决定 | 仍不能据此声称 |
| --- | --- | --- |
| 全虚构Map无法兑现听歌发现 | 精选真实合作、来源、官方作品链接；原虚构图独立保留 | 海量曲库、内置播放器、个性化推荐效果 |
| 真人只换两张预置图 | 自定义活动与个人压缩照片，授权读取和交换快照 | 已有真实活动用户、照片自动到场认证 |
| 相册也能收照片，为什么换卡 | 同时刻／不同视角解释，定向确认，共同署名纪念 | 单项机制首创，或双人流程必然优于相册 |
| 空房间没有第一份收益 | 一个人可保存自己的现场卡PNG，邀请后再选择交换 | 已解决陌生人社交冷启动 |
| Map与Space叙事容易分散 | Space主线、Map可选；不伪造真实艺人与演出关联 | 线上发现到线下到场的转化已被验证 |
| 视频是截图编排 | 通过现有页面的真实录制能力补操作视频，材料逐项标版本 | 未录制部分的流程已经录像证明 |

## 暂不追加的能力

不追加开放广场、附近的人、私聊、票务、模型权重、AI分数或完整图库后台。初赛公开口径没有强制实时AI推理，但这不是“只靠AI Coding即可获奖”的结论。对用户有收益的模型任务，应有单独理由和真实调用证据。

## 下一轮的判断依据

实际代码与材料完成状态只以[项目状态](../../../docs/PROJECT_STATUS.md)为准。少量真实观众试用应比较照片／群聊与双联体验，收集具体交换动机及主动回应；竞品报告提供了可否决的决策条件。没有进行用户招募或编造用户数据。

本次复盘能提高内容和交付的说服力；不能推算奖项、评委偏好或获奖概率。
