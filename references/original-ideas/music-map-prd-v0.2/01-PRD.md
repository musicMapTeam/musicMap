# Music Map 产品需求文档 v0.2

日期：2026-09-26  
状态：首版需求基线；沿途发现清单的呈现与操作已细化，供原型和开发对照。界面视觉风格尚未确定，数据与素材可用性仍需验证。

本稿依据发起人的最新确认整理。承载方式、清单构成、本地保存、回退计步及 v0.1 中功能规则建议已获用户接受，除本次明确移除或调整的内容外均转为首版需求。第 5 节是本次委托补充的清单呈现方案。文中的「待验证」仅指实际资源或实现依赖，不代表要求用户再次确认已接受的产品规则。

## 1. 项目目标与边界

### 1.1 产品定位（已确认）

面向年轻、重度使用 QQ 音乐、关注艺人且愿意探索的听众，以具有空间感的艺人关系网，让用户从熟悉的华语流行艺人出发，发现相关艺人和音乐，并留下探索结果。

第一版包括：自由漫游、沿途发现清单、步数挑战。漫游优先支持合作关系与风格联系，具体内容依赖数据核验。首批内容从周杰伦等熟悉艺人的关系圈向外延伸，同时纳入关系可信、用户可能不熟悉的艺人。暂不承诺艺人或歌曲数量。

“用户因为关注熟悉艺人而愿意探索关联艺人”是产品假设，需要后续试用验证，尚无真实用户研究结论。

### 1.2 承载方式与赛道（已确认）

参赛赛道：创新音乐产品。

产品作为独立、可直接通过浏览器访问的手机网页运行。QQ 音乐年轻重度用户是首批目标人群，产品无须连接 QQ 音乐账号。搜索、探索、试听、留下歌曲、结果回顾均在 Music Map 内完成。

首版移除 QQ 音乐接入、第三方收藏同步、创建平台歌单、外跳按钮以及独立艺人主页。艺人相关操作集中在地图锚点、作品试听区和发现回顾中；回顾中的艺人可作为新漫游起点，不进入艺人详情页面。

### 1.3 核心体验（已确认）

- 手机优先；关系网具有空间感，拖动时产生旋转感，不要求具象地理地球。
- 点击周围艺人，该艺人以连续的空间移动成为中心锚点，避免突然整页切换。
- 点击当前中心头像，展开其个人代表作试听区；再次点击同一头像，收起试听区。
- 代表作目标为 3—5 首，实际展示依内容及试听资源决定，不虚构缺失作品。
- 保留返回上一锚点、返回本次探索初始锚点的能力。
- 挑战轻松、无时间上限、无步数上限；完成后展示“X 步到达”和途经艺人、连接作品。

## 4. 自由漫游需求

### 4.1 选择起点

已确认：用户通过搜索自行选择艺人起点。

操作规则：

- 搜索仅覆盖实际收录的艺人；提示当前内容范围，不能把未收录写成“该艺人不存在”。
- 有同名艺人时展示可辨识信息，使用唯一标识区分。
- 搜索为空或没有结果时，提供少量真实可用的示例起点，搜索仍是主要入口。
- 选择艺人后建立本次漫游，记录初始锚点、当前锚点、关系模式和探索路线。

### 4.2 关系模式

合作关系：以具体作品或录音版本的署名为依据。第一版优先共同演唱；是否扩展作词、作曲、制作，待数据样例确定。每条关系显示准确角色，不能仅因为同一张合辑出现两人，或两人分别翻唱同一作品，就标成合唱。

风格联系：根据经过整理的流派标签或相似度结果推荐。需说明依据，例如共同风格标签；不能将它标成合作事实或受众重合率。艺人可以有多种风格，单首作品的标签不自动代表艺人全部风格。

切换模式时保留当前艺人与已有路线，只更新下一步可探索的关系。路线逐段记录当时使用的关系类型。默认进入合作模式，用户可切换到已验证可用的风格模式；切换本身不增加路线节点。

### 4.3 拖动、选中与返回

| 操作 | 预期结果 | 状态 |
|---|---|---|
| 拖动关系网 | 产生旋转感，查看其他相邻艺人；不自动切换中心、不增加路线节点 | 已确认 |
| 点击相邻艺人 | 通过连续动效移动至中心，更新该艺人的关系，记录一次艺人间移动 | 已确认 |
| 点击中心头像 | 展开代表作试听区；再次点击收起；不增加路线节点 | 已确认 |
| 返回上一锚点 | 回到当前路线的上一艺人，恢复当时模式与视角，撤销当前路线的最后一段 | 已确认 |
| 返回初始锚点 | 回到本次起点，当前路线恢复为起点；主动留下的歌曲保留；已走过的轨迹仍保留在本次探索记录中 | 已确认 |

“当前路线”用于判断当前从哪里来；“探索记录”保留本次已经走过的分支，供结束时回顾，两者不混算。

从邻居再次进入已访问艺人，视为新的探索动作并记录；点击当前中心头像属于展开操作。拖动不能误触头像。连续快速点击时，最终的中心、名称、关系和试听内容必须一致。已经位于起点时，相应返回操作不再改变状态。

视觉风格、动画时长、节点数量、布局及线条样式留待原型阶段确定。减少动画或低性能设备的处理方式由开发验证，但返回和探索操作必须可用。

### 4.4 作品试听与留下歌曲

中心头像下方展开个人代表作试听；用户再次点击可收起。代表作由产品先整理或审核，不能将数据库随意返回的前几首直接称为代表作。试听区不提供艺人主页或外跳入口。

操作规则：

- 代表作与“连接两位艺人的作品”分别标识；风格联系可能没有共同作品，不强行补一首合作歌。
- 试听只在用户主动操作后播放，同一时刻只播放一首。
- 收起试听区时暂停；切换中心艺人时停止原试听；展开新中心时展示新艺人的内容。打开关系依据、发现清单、挑战结果或离开当前界面时也暂停原试听，避免界面切换后出现来源不明的声音。
- 没有试听资源的曲目明确标注不可试听；可用作品不足 3 首时展示实际数量。
- 代表作及合作关系作品均提供“留下”操作，成功后变为“已留下”，并更新本次发现数量；不要求注册或登录。
- 播放与“留下”是独立操作：试听不自动收藏，留下歌曲也不要求先听完。暂无试听的曲目仍可留下文字资料，并保留“暂无试听”标记。
- 返回或刷新恢复会话后，音频由用户再次点击才播放。

音频全部不可用时，不能将无声播放状态作为完成验收；需重新讨论资源与首版范围。

## 5. 沿途发现清单：本次发现与探索回顾

### 5.1 目标与呈现原则

让用户带走自己选中的音乐，并能回看“我是怎么走到这里的”。内容包括路线、途经艺人和主动留下的歌曲；漫游时轻量记录，结束时集中回顾。默认先展示用户主动留下的歌曲，路线和艺人按需展开，避免手机首屏充满长关系网。

以下仅规定信息顺序与操作，配色、字体、图形风格和精确布局在原型阶段确定。产品内入口分别使用“本次发现”和“我的发现”，避免把浏览过的艺人直接宣称为用户此前从未听过的艺人。

### 5.2 漫游过程中的入口

- 地图保留轻量入口“本次发现 · N 首”；N 只统计本次主动留下的不同曲目，不是试听次数或途经歌曲数。N 为 0 时仍能打开。
- 用户点击后打开可关闭的清单面板，查看歌曲，并展开路线或途经艺人；关闭或选择“继续漫游”恢复原锚点、模式和视角，操作不增加路线节点。
- 点击“留下”只给予简短成功反馈，不强制弹出清单、不打断探索。同一曲目在面板和试听区的状态保持一致。
- “结束探索”入口可以直接找到，不要求用户先收藏歌曲。点击后暂停音频，保存本次记录并进入回顾。

### 5.3 结束回顾的信息顺序

| 展示顺序 | 内容 | 可做的事 |
|---|---|---|
| 1. 本次概览 | 探索日期、起点、去重后的途经艺人数、主动留下的歌曲数 | 了解这次探索留下了什么；不按速度或步数排名 |
| 2. 留下的歌曲（默认展开） | 曲目名、艺人、可用封面、试听状态；附发现来源，如“在某艺人的代表作中留下”或“通过 A 与 B 的合作作品留下” | 单曲试听、移除；保留试听不可用时的文字资料 |
| 3. 我走过的路（可展开） | 手机可纵向滚动的行程，按探索顺序呈现实际艺人移动与连接依据 | 查看每段合作歌并试听或留下；风格段查看风格依据 |
| 4. 途经艺人（可展开） | 按首次访问顺序去重的头像、名称；含起点，重复访问不重复计数 | 在已结束的回顾中选择“从 TA 再出发”，新建自由漫游 |
| 5. 后续行动 | 继续本次探索、开始新探索、回到起点搜索页 | 所有后续操作留在 Music Map 内 |

概览中艺人数只计真正成为过锚点的艺人，不计仅在周围显示、未访问的头像。合作作品自动属于路线依据，但只有主动点击“留下”才进入歌曲清单；风格关系没有共同作品时只展示风格依据。

回顾的首要用途是重新试听和继续发现。首版提供单曲试听，不引入连续播放、循环、随机等完整歌单播放器能力。

### 5.4 回退和分支怎样显示

保存“当前路线”和“完整探索记录”两种信息：当前路线支持导航；完整探索记录生成行程回顾。界面只将实际沿关系走过的移动画成有依据的连接。

例：用户走过 A → B → C，返回 B，再从 B 走到 D。回顾按时间展示“A → B → C”，随后以文字分隔提示“返回 B，换个方向”，再展示“B → D”。不能把 C 与 D 直接连起来，也不能把快捷返回当成新合作。

- 返回起点同样用“返回起点，重新探索”的分隔提示，下一段从起点继续。
- 实际沿邻居重新走入旧艺人，保留这次真实移动；途经艺人数仍去重。
- 只切换模式不产生连线；下一段关系注明实际使用的模式。
- 长路线按段展示、按需加载，完整信息可访问，不强行压成一屏或一张图片。

### 5.5 歌曲的收录、移除与来源

- 按曲目的稳定标识及版本去重；同一首不同录音版本可分开记录，不单凭歌名去重。
- 歌曲按首次留下的顺序排列；多次遇到同一曲目不增加歌曲数量，可在详情中保留多个发现位置。
- 已留下的曲目再次点击“已留下”可移除，也可在清单中移除；反馈中提供撤销，避免误触后难以找回。
- 移除歌曲不删除其真实路线依据。重新留下恢复到当前清单末尾；撤销误移除则恢复原位置。
- 收录来源记录艺人或关系及作品信息，用户日后仍能理解为什么留下它；无需外跳至第三方页面。

### 5.6 保存、历史与再次探索

- 数据在探索过程中持续保存至当前浏览器；“结束探索”将同一记录标记为已结束，并展示回顾。连续点击结束、返回再打开，不重复生成记录。
- 起点搜索页提供“我的发现”入口，按最近更新时间显示本地保存的漫游回顾和挑战记录，以类型标记区分。每条显示日期、起点或起终点、留下歌曲数；不必新建独立社区或账号系统。
- “继续本次探索”恢复该记录最后的锚点、模式、视角、当前路线与清单，在同一条记录上继续；再次结束更新原记录。
- “从 TA 再出发”或重新选择起点会新建漫游，保留旧回顾，新清单从空开始；如果当前已有进行中的漫游，明确提示“结束当前探索并开始新的探索”，保存后再切换。
- 漫游历史中的艺人只用于设定新起点，不进入艺人主页。数据更新后若艺人已不可用，保留历史文字，并提示改选当前可用起点。
- 支持删除一条本地记录，操作前明确对象并确认；删除后不影响其他探索和挑战。
- 保存失败时显示“本次未能保存，请重试”等可理解反馈，并保留当前界面内容；不假装保存成功。
- 首版不承诺跨设备同步；清除浏览器数据可能移除历史。提示放在历史保存说明处，不在每次探索中打断用户。

### 5.7 空状态与资源失效

| 情况 | 呈现与处理 |
|---|---|
| 没有留下歌曲 | 显示“这次还没有留下歌曲”，仍可查看路线和艺人，允许继续探索；不自动填歌 |
| 仅选了起点就结束 | 展示起点、1 位途经艺人和真实歌曲数量；路线说明“还没有走到下一位” |
| 尚无历史记录 | “我的发现”展示开始探索的入口，无虚构历史 |
| 歌曲或头像资源失效 | 文字与关系仍可查看，头像使用姓名占位，曲目标注暂无试听；不阻断回顾或强制外跳 |
| 数据源更新 | 历史保留当时记录的艺人、关系与作品说明；不能被新关系悄悄改写。音频可用性按当前实际情况显示 |

### 5.8 个人发现卡片（可选增强）

主流程、试听和本地回顾完成后，有余力才做图片导出。卡片展示起点、途经艺人和留下的歌曲摘要，长内容明确标注为节选；不把截断的路线伪装成完整路径。导出由用户主动操作，不自动发布。图片不代替网页中完整、可操作的回顾。参赛作品封面仍按第 2 节单独准备。

## 6. 步数挑战

### 6.1 用户确认的规则

- 用户自行选择起点与终点。
- 第一版只沿合作关系挑战。
- 不设置时间限制，不设置步数上限；不以倒计时或惩罚制造压力。
- 到达后展示“X 步到达”，可视化艺人路线与每段连接作品。
- 结束后可以再次挑战，返回选择起终点的页面；也可以返回漫游。

### 6.2 补充规则（已接受）

| 情况 | 规则 |
|---|---|
| 起点或终点未收录 | 明确范围，允许重新搜索，并提供实际可选艺人 |
| 起终点相同 | 提示选择另一位艺人，不直接发放 0 步通关结果 |
| 两点在当前合作网络中不可达 | 开始前说明“当前已收录关系暂未连通”，保留选择供修改；不宣称现实中没有关系 |
| 合法移动 | 从当前艺人沿一条已核验、可用于本局的合作关系到相邻艺人 |
| 步数计算 | 当前路线每经过一段艺人间合作关系增加 1 步；拖动、试听和查看关系不计步 |
| 返回上一位 | 撤销当前路线最后一段，步数减 1；这是路线回退，不是失败或处罚 |
| 返回本局起点 | 重置当前挑战路线与步数，保留起终点；给出简短确认以免误操作 |
| 沿关系重新走到已访问艺人 | 允许，作为一次新的合法移动计步，不要求最短路线 |
| 同一对艺人有多首合作歌 | 每段记录实际选用的连接作品；若不让用户选，由程序按固定规则选定并显示 |
| 选择到达终点的合法邻居 | 该次移动完成后进入结果页 |
| 想中途退出 | 可返回漫游，不显示挑战失败，不强制继续 |

本稿中的“X 步”表示最终保留路线的关系段数，不是全部点击次数，也不包含已经撤销的试探路径。结果不声称是最短路径。

本局合作关系的定义与数据版本固定；挑战不允许临时切换风格关系作为捷径。视野未展示的合法邻居应能通过拖动或其他明确方式访问，不能把必要路径永久藏起。

### 6.3 挑战与漫游的衔接（已接受）

- 从漫游进入挑战时，先保存漫游会话；两者分别记录，避免挑战操作覆盖原探索路线。
- 挑战进行时独立保存当前路线和用户留下的歌曲；完成后自动将同一挑战记录标记为完成，保存最终路线、连接作品和主动留下的歌曲，允许从“我的发现”回看。返回上一位撤销的分支不出现在“X 步到达”的最终路径中。
- “再次挑战”回到起终点选择页，上一局结果先保存，新局不沿用上一局步数。
- “返回漫游”优先恢复进入挑战前的漫游会话；若无原会话，成功后从挑战终点开启新的漫游，中途退出则从退出时当前艺人开始。挑战歌曲保留在该挑战记录中，不自动混入原漫游清单。
- 中途退出的挑战保留为“未完成”，可在“我的发现”中继续原局或删除，不显示失败惩罚；恢复时沿用本局图谱和规则，资源缺失需说明。

### 6.4 挑战结果的呈现

结果页先展示“X 步到达”和起终点，再展示最终有效路线：艺人是节点，具体合作作品是节点间的连接依据。长路线允许纵向滚动或分段展开，完整路径可查看；回退操作与已撤销分支不加入最终计步结果。

每段连接作品可单独试听或留下；不能把歌曲标题当成一个额外跳转节点重复计步。“沿途连接作品”和“我留下的歌曲”分别显示，默认不会收藏整条路径的作品。结果页提供再次挑战、返回漫游和查看本次留下歌曲的操作。

成功后显示的 X 步只等于最终有效路径段数，与途经艺人去重数量或歌曲去重数量无固定等式；多次走访同一艺人、同一作品可导致这些数量不同。

## 7. 数据、音频与头像的协作要求

产品负责人定义内容范围、关系语义和展示要求；开发负责人验证数据获取、整理、接入、播放及部署；双方共同抽查事实和真实体验。头像、试听资源的技术寻找和接入由开发主导，最终内容是否合适由产品参与判断。

| 对象 | 产品需要的信息 | 开发需要验证的事项 |
|---|---|---|
| 艺人 | 唯一标识、名称与别名、区分同名人的信息、简介、代表作 | 数据覆盖、身份匹配、缺失与更新情况 |
| 合作关系 | 两位艺人、具体作品或版本、各自角色、资料来源、核验状态 | 能否追溯，避免误把合辑、翻唱、同名作品当成共同演唱 |
| 风格联系 | 风格标签或相似结果、计算或整理依据、适用范围 | 标签一致性、艺人粒度、是否含足够的华语内容 |
| 音乐 | 曲目标识、标题、艺人、版本、来源链接、试听可用状态 | 音频来源和允许使用方式、有效期、手机可播放性；数据表不等于音频文件 |
| 头像 | 图片来源、对应艺人、允许使用方式 | 地址可用性、加载与存储方式、人物是否匹配 |
| 探索与挑战记录 | 会话标识与类型、状态、起终点、当前锚点与路线、完整探索事件、关系及作品快照、模式、数据版本、更新时间 | 保存、回退、重置、恢复、删除是否正确；漫游与挑战互不覆盖，重复结束不生成重复记录 |
| 留下的歌曲 | 稳定曲目标识及版本、收录顺序、发现来源、所属会话 | 去重、移除与撤销、各处状态同步；不将浏览或试听自动计为留下 |

头像暂缺时使用姓名或首字占位，避免错配真人或用生成头像冒充真实艺人。封面和简介也只展示已经核验、可用的内容。资料来源链接用于核验，不因此增加面向用户的外跳入口。

用户希望出现不那么知名的艺人。从真实合作或风格关系中寻找有探索价值的对象；不为增加陌生感而随机插入无依据的艺人。收录名单与覆盖数量在查看实际数据后确定。

## 8. 验收清单

以下按本版需求逐项验收；资源缺失须如实记录，不能以动画或占位状态代替真实功能。

### 8.1 产品验收

- [ ] 能在手机上搜索真实收录艺人，空结果和同名情况有清楚反馈。
- [ ] 拖动有连续空间反馈，点击邻居后中心与信息一致，拖动不误触。
- [ ] 中心头像可展开、收起试听，操作不误计为一次艺人移动。
- [ ] 返回上一位、返回起点符合约定，并恢复相应模式与视角。
- [ ] 每条合作关系能看到依据；风格联系与合作事实有清楚区分。
- [ ] 不熟悉的艺人有真实关系与可理解的探索理由。
- [ ] 试听在目标手机环境真实工作；失败有说明，单次只播放一首。
- [ ] 展开清单、切换锚点、收起试听或离开界面时暂停原音频；返回和刷新不会自动播放。
- [ ] 本次发现数量只统计主动留下的不同曲目；反复试听不增加数量，同一版本重复留下不重复计数。
- [ ] 回顾先展示留下的歌曲，路线与艺人可展开；没有留下歌曲、仅访问起点也能正常结束回顾。
- [ ] A → B → C、快捷返回 B、再走到 D 的回顾保留实际分支，不出现虚构的 C → D 连线；切换模式不生成移动。
- [ ] 移除歌曲不删除路线依据，撤销可恢复原顺序；代表作区、连接作品区与清单的留下状态一致。
- [ ] 同一探索反复结束、打开回顾不重复保存；继续本次探索更新原记录，从其他艺人再出发新建记录并保留旧回顾。
- [ ] 刷新可恢复已保存内容；删除一条记录不影响其他记录；保存失败有明确反馈。
- [ ] 挑战起终点由用户选择；不可达在开始前反馈，不伪造路径。
- [ ] 没有计时限制和步数上限；移动、回退与结果页步数一致。
- [ ] 挑战结果中的每段作品确实支持对应关系；再次挑战与返回漫游有效。
- [ ] 回退减 1 步、重置归零、沿真实关系再次访问旧艺人加 1 步；撤销分支不进入最终挑战路线，结果不宣称最短。
- [ ] 挑战与漫游各自保存路线和留下的歌曲；中途退出不显示失败，恢复原局不偷偷更换关系规则。
- [ ] 长路线、缺图、缺试听、本地存储失败等情况不会让核心流程卡死。
- [ ] 全流程在独立网页中完成，不出现 QQ 音乐接入、平台歌单同步、外跳或艺人主页按钮。

试用时观察：用户能否不依赖口头指导完成漫游和挑战；是否理解两类连线；是否主动听歌或留下歌曲；是否发现自己此前不熟悉且愿意继续了解的艺人。记录样本数量、操作困难与实际行为，不把“点击收藏”表述为长期留存，不把原型示例表述为用户测试结果。

### 8.2 初赛提交验收

- [ ] 队伍信息完整，作品名称在各处一致，赛道选择“创新音乐产品”。
- [ ] 作品介绍及创作思路为 100—300 字，说明用户问题与解决方案，描述与实际 Demo 一致。
- [ ] Demo 已部署为可直接访问的在线网页；用手机从提交链接重新打开，验证核心流程，不依赖开发者电脑上的预览服务。
- [ ] 演示视频不超过 3 分钟，文件大小在 500M 以内，含语音讲解或字幕；产品思路及核心功能清晰，无水印、无杂音，原创合规。
- [ ] 准备并上传 1 张作品封面或效果截图；不以尚未开发的个人发现卡片功能代替该材料。
- [ ] 2026 年 10 月 9 日截止前完成实际提交，检查提交成功状态和已上传材料，而非只在本地准备完毕。

## 9. 推进顺序与剩余依赖

1. 开发先提供一小组可核验的艺人关系、代表作、试听与头像样例，验证手机播放、关系连通与风格依据；产品同步准备页面流程和视觉参考。
2. 根据资源验证结果落实首批收录名单和合作角色范围；若资源无法支持风格模式或核心试听，明确提出范围调整，不用虚构内容顶替。
3. 产品完成手机原型，覆盖搜索、漫游、代表作、关系依据、本次发现、结束回顾、历史记录、挑战设置与结果，以及必要空状态。页面可合并为面板，不要求每项都做独立页面。旧 HTML 外观不作为已认可方案。
4. 开发按本版规则实现并尽早部署；产品在真实手机上边体验边记录问题，优先保证从进入到回顾、从开局到结果的完整流程。
5. 验收与小规模试用后修复影响主流程的问题。个人发现卡片仅在必需功能及参赛材料均有保障时考虑。
6. 产品准备 100—300 字介绍、演示视频和作品封面，双方核对实际功能、在线链接与提交信息，完成正式提交。

建议内部以 **10 月 8 日完成可提交版本与材料**为目标，给 10 月 9 日的上传、链接检查和问题修复留出余量。这是内部排期建议，具体分工日期仍需结合双方可投入时间安排；官方提交截止不变。本稿规定产品行为与信息呈现，没有指定技术框架或完成视觉原型。
