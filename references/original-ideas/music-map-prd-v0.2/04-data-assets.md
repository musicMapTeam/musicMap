## 2. 可以考察的公开数据入口

以下仅确认存在相应公开入口，没有替团队下载、清洗或完成华语覆盖抽样，也未确认某个 Hugging Face 数据集已适用。

| 来源 | 可考察的内容 | 仍需验证 |
|---|---|---|
| [MusicBrainz 数据下载](https://musicbrainz.org/doc/MusicBrainz_Database/Download) | 官方提供数据库快照；核心目录包含艺人、发行、录音等；流派关联需关注衍生数据中的标签 | 华语覆盖、共同演唱署名完整性、艺人匹配与字段粒度；不同下载包许可不同，不能一概视为同一种许可 |
| [Wikidata 许可说明](https://www.wikidata.org/wiki/Wikidata:Licensing) | 结构化数据可用于身份信息等候选补充；结构化数据采用 CC0 | 具体条目字段和完整性；链接出去的图片、音乐不因此一并获得使用许可 |
| [Hugging Face 数据集卡说明](https://huggingface.co/docs/hub/datasets-cards) | 可通过数据集卡检查来源说明、用途和许可元信息 | 必须明确到具体数据集、版本和文件；下载可用不等于关系可信、华语覆盖充分或音频可用于公开作品 |

MusicBrainz 官方下载说明将核心包与部分衍生包分别列于不同许可下；如选用风格标签，需核对实际文件及其条款。以上入口不自动提供可公开播放的音乐片段。

头像和音频尚无已确认来源。首版头像可使用姓名占位；真实试听属于核心体验，需要开发实际验证后决定，不把“数据库里有歌名”当成“已有可播放音频”。

## 3. 产品字段字典

### 艺人 artist

| 字段 | 必需 | 含义 / 校验 |
|---|---|---|
| id | 是 | 稳定且唯一；全系统用 ID 关联，不用姓名作主键 |
| name / aliases | 名称必需 | 搜索与展示；同名人额外提供 disambiguation 区分 |
| sourceRefs | 是 | 至少一个可核验来源登记 ID；虚构样例另标 fictional |
| avatarAssetId | 否 | 已登记图片素材 ID；缺失时显示首字 |
| representativeTrackIds | 是 | 目标 3—5 首；不足按实际展示，不造歌、不强称数据库前几首为代表作 |
| styleTags | 否 | 标签名称、来源与适用说明；不直接写未经验证的受众重合率 |

### 歌曲 / 录音 track

| 字段 | 必需 | 含义 / 校验 |
|---|---|---|
| id / title | 是 | 稳定录音或曲目标识、标题；不同录音版本不能只按歌名合并 |
| artistIds / version | 是 | 实际演唱者与版本标记，例如录音室版、某次现场版 |
| sourceRefs | 是 | 曲目及署名来源 |
| previewAssetId | 否 | 对应音频资源 ID；为空显示暂无试听 |
| coverAssetId | 否 | 对应封面资源 ID；缺失不阻断播放与留下 |

### 艺人关系 relation

| 字段 | 必需 | 含义 / 校验 |
|---|---|---|
| id / fromArtistId / toArtistId | 是 | 稳定关系 ID 与两端艺人，禁止端点不存在 |
| type | 是 | cooperation 或 style |
| evidenceTrackIds | 合作必需 | 至少一个确实连接两人的录音版本 |
| roles | 合作必需 | 记录两端在对应作品中的准确角色；首版优先共同演唱 |
| reason / sourceRefs | 是 | 可解释依据及来源，不能用“算法算的”代替说明 |
| verificationStatus | 是 | pending / verified / rejected；正式合作挑战只使用 verified |
| graphVersion | 是 | 本局图谱版本，挑战中固定，不临时改变合法边 |

风格模式可由共同标签或有说明的相似结果建立；不必有合作作品，不把风格推断写成合作事实。合作边存在多个作品时先按已审核的展示顺序选一个，固定到该次移动快照；原型每边只有一首。

### 图片与音频 asset

| 字段 | 必需 | 含义 / 校验 |
|---|---|---|
| id / type | 是 | image 或 audio，供曲目与艺人引用 |
| sourceUrl / sourceRef | 是 | 原始资源及来源登记；用于团队核验，不新增产品外跳按钮 |
| servingUrl | 可用时必需 | 实际可加载地址；勿把临时受保护地址当长期地址 |
| licenseOrPermission / attribution | 是 | 许可或授权记录、所需署名；未知必须写 pending |
| availability / checkedAt | 是 | pending / available / unavailable，最近核验时间 |
| mimeType / durationSeconds | 音频时核验 | 实际格式与片段时长，以资源允许范围为准，不预设统一 30 秒 |

## 4. 本地会话所需内容

- sessionId、漫游或挑战类型、进行中或结束状态、创建及更新时间。
- 初始锚点、当前锚点、模式、视角、当前导航路径；每段保留关系和作品快照。
- 漫游事件序列：真实移动、快捷返回、回起点；不能将导航事件伪造为关系。
- 主动留下的曲目 ID、版本、顺序和发现来源。试听操作与收藏操作分别处理。
- 挑战目标、固定图谱版本、原漫游会话 ID；挑战结果以当前有效路径段数计算。

JSON Schema 只约束数据目录基础结构，不替代引用完整性、关系事实和资源播放测试。会话数据的存储方式由开发选择；不需要为原型接数据库。

## 5. 真实内容的准备顺序与交付标准

1. 先拿一组能形成真实连接的华语艺人、合作曲目和有效试听做验证；同时检验“熟悉艺人连接不那么熟悉艺人”的内容机会。
2. 逐条核对身份、录音版本和共同演唱角色；不把合辑同台、分别翻唱或同名作品当合作。
3. 标记可用图谱分量；挑战起终点选择前校验连通性，不提前给用户承诺任意两人都能到达。
4. 再验证风格依据，无法说明的关系不进入正式版本。
5. 逐项补全资源登记、字段引用与手机试听结果；数量扩大前，先让一个完整真实路径可以使用。

开发交付给产品：数据文件、字段说明、来源登记、已核验关系样例、可播放样例和未解决问题。产品返回：代表作选择、展示文案、事实疑点及需要保留的探索路径。缺失项如实标记，不能把“待验证”改写为“可用”。
