# 樱下放映 · 夜场 · 视觉规范

2026-09-29 · MVP **0.16.0** / 产品文档 **3.0**。本文沿用原文件路径，记录当前唯一的樱花艺术方向；完成证据见[项目状态](PROJECT_STATUS.md)，业务规则见[产品方案](../product/docs/01-product-plan.md)。

## 艺术方向

用户于 2026-09-27 明确：“优秀的视觉包装是我们项目能否成功的根本”。0.15 把「樱下放映」从晴天午后改为傍晚到夜场演出，并将「樱下放映 · 夜场」冻结为最终美术方向。后续只做打磨，不再换方向。

0.16 起应用只有 Music Map（用户 2026-09-28 的决定，细节待与产品负责人对齐）。夜场方向、配色与灯光取值不变，小院改讲一家夜场唱片店的故事：樱树下的小院里，只有唱片店还亮着灯。门口的首页请你说出一位喜欢的歌手；店里的唱片桌摊开真实合唱的关系网，寻声时唱片背面朝上，一张张翻开；收藏架是「我的发现」，放着走过的路和留下的歌。树下舞台留作没有操作的听歌角。界面沿用店里的物件：题签、手牌、封套、票条、歌单与收藏卡。

主色为：夜空靛紫（theme-color `#23214a`）与地平线暖辉、串灯琥珀、暖纸、樱粉和鼠尾草绿。夜空上的文字用奶油色，导航与右上按钮用深色玻璃；纸件是带夜间灯光阴影的暖纸，焦点环为琥珀色。清楚的中文、歌名、署名与来源占据操作层。WebGL 不可用（`body.spatial-fallback`）时，外壳回到浅纸深字。

构图变化度 / 动态强度 / 视觉密度采用 **(7, 4, 3)**，范围 1–10，只表达设计取舍，不是质量评分或设备性能指标。

| 部位 | 当前表达 |

说明放在用户需要决定的位置。保留作品来源、「朋友出的题」、示例标记、保存失败与实际错误，不用段落解释可见的按钮。长内容正常滚动，不裁掉操作。页面沿用 OverlayScrollbars 2.16.0 自动隐藏细浮动条，弹窗保留原生滚动。

### 共同的界面材料

- **暖纸与细墨线**：题签、手牌、封套内页、歌单、回顾纸页和收藏卡共用纸色、边线、纸角和夜间灯光阴影，避免每页另起一套卡片组件外观。连线歌单的歌名票条与分享卡片的票根沿用同一套票据语言：打孔边或缺口、虚线撕线、印章。
- **可读的中文**：正文不小于 14px，辅助文字不小于 12px；0.15 清理了原先 9–11px 的小字。温度章和印章用文字字形表达，不只靠颜色。
- **物件与索引**：唱片可点、手牌可翻；分类和路线使用短索引。署名、来源与确认使用清楚的 HTML 控件，不把长文字烘焙进模型。
- **操作有位置**：艺人入口跟随唱片投影，作品内页从唱片桌打开。物件、投影标签和底部索引调用同一业务动作。
- **主次与留白**：场景承载探索，细节按需展开。提示、错误与撤销保持可见，装饰不覆盖点击区域。

## 空间与动作

`#sakura-world` 保留同一 Three 场景，导航与实物点击复用相同操作。手机独立机位，HTML 层承担搜索、署名、确认与错误反馈。

| 机位 | 空间位置 | 操作 |
| --- | --- | --- |
| `home` | 小院、开放的唱片店与树下听歌角 | 「唱片店」标记进入唱片店；首页纸卡从歌手出发漫游或开一局寻声。听歌角没有操作 |
| `explore` | 唱片店内的音乐关系桌，由桌灯照亮 | 寻声：翻开、前往、提示、揭晓、连线歌单、出题给朋友；完整图鉴：点相邻歌手前往、点线看作品、和 TA 隔几首；拖动、缩放与适配全图 |
| `records` | 店内收藏架 | 我的发现：探索记录与留下的歌 |

旧的 `live` / `editor` / `photo` 机位随 Space 退出：旧视图名 `space` / `live` 落到 `home`；旧的 `editor` / `photo` 场景动作被忽略，不再触发任何操作。GSAP 3.15.0 驱动镜头；连续选择从当前位置接续，中断旧动画。关闭弹窗回基础机位，替换弹窗不抢镜头。减少动态时直接显示目标。唱片慢转、花瓣与猫的呼吸保持轻量，镜头与动画不自动保存、下载或分享。

夜场光照集中在 `sakura-scene.js` 的 `NIGHT` 常量和 `sakura-world.js` 的材质中：

- 天空是世界固定的靛紫渐变，地平线有暖辉。
- 月光是唯一投影的光。另有店内暖光、左右两组串灯的点光与 17 个灯泡光晕、照亮听歌角的 par 灯与光束，以及亮窗远屋和自发光夜樱。
- 灯的数量在运行期固定，机位切换只补间强度，不触发重新编译；收藏机位另把店内暖光移到右侧吊灯下。
- 唱片桌在 `explore` 机位由 `tableSpot` 照亮。
- 首次挂载且没有减少动态偏好时，场景先暗两帧，再在不超过 1.4 秒内逐组亮灯；减少动态时灯光直接到位。
- 光晕与光束不参与拾取。调色与墨线参数由本项目设定，手机暗角降低。

0.14 起用纸件的实际占位共同构图：测量可见面板、菜单和弹窗，按唱片桌或收藏架的几何边界适配剩余区域。透明容器不挡点击；展开、收合、窗口缩放后重新取景。标签与实体共享可见区域，名字之间避碰，轻微移位时用短线指回唱片。极短屏收起重复标题与数量，保留可操作的文字大小。

手机弹窗使用下方工作纸，暂时收起不可操作的导航；短屏纸页整张滚动，错误和末尾动作可达。

### 唱片桌与寻声

唱片桌的确定性布局按数据集与关系类型缓存，寻声与完整图鉴使用同一组位置，选择或翻开都不重排。0.16 真实精选为 29 位艺人、37 条共唱边，一个连通分量、9 个独立回路；布局按距离确定并做间距整理，艺人多时封套缩小。乐团节点五月天在面板上标「乐团」。场景排布只服务构图，不表示音乐相似度、地理位置或算法评分。

进入唱片店默认一局寻声，画面由以下几部分组成：

- 左上是题签：小标「寻声 · 真实合作精选」（朋友链接为「寻声 · 朋友出的题」），大字问题，状态行写步数、认识与翻开数量。用过提示 ① 后，题签加「还隔 N 首」和温度章。
- 右上最多三个主控件：提示、换一组、目录。其余入口收进目录：自选起点和终点、把这道题发给朋友、放弃并揭晓、完整图鉴、开放曲库与我的发现。
- 桌面上，起点有光圈，终点有「终点」签。未认识的唱片是纸背封套加「？」，不带名字、颜色或数量；桌上只画已翻开的合作。
- 底部手牌列出所在歌手的全部合作。未翻开的只写歌名；翻开时卡片翻面，桌上唱片翻正，墨线从当前歌手生长到对方。
- 提示 ② 在对应手牌贴「试试这张」签，桌上从当前唱片画一段带箭头的铅笔残段，不能点。短屏手机（宽 ≤ 760 且高 ≤ 640）隐藏提示便签、手牌收成单行，提示改在按钮里写「翻开 · 试试这张」。
- 手机竖屏在高 > 2.3×宽时使用竖向机位；手机的唱片店机位把纸桌放进顶部工具与底部手牌之间的空白区域。

抵达时整桌按与终点的距离依次翻面，路线逐段描成金色，再打开「连线歌单」。揭晓时，用虚线墨画出本专题的一条最短路线，用户自己的路线保持实线。连线歌单是竖排 setlist：唱片封套与歌名票条交替，票条带打孔边，写版本与来源，可展开署名；有 QQ 同版本的票条另有「去 QQ 音乐听」（`b5939d9`，已上线）；歌单上方是「这道题，也给朋友走一走」，放「出题给朋友」「保存战绩卡」「换个起点再出一题」，底部是「再来一局」「留下这 N 首」「看完整图鉴」。注脚写明“最短”只指本专题收录范围、无内置音频。仪式可跳过；减少动态时直接显示终态并打开歌单。WebGL 不可用时，播放约 0.9 秒加路线每段 0.3 秒（走 3 首抵达约 1.8 秒）、可跳过的二维仪式。

答案在翻开、提示或揭晓之前不出现：搜索、各面板、二维 DOM、读屏文字、三维封面和投影标签都只读同一可见集合。局中关闭署名表，因为署名会出现尚未认识的艺人名；抵达或揭晓后在歌单中开放。朋友的题目链接只带起点和终点，打开后同样从迷雾开始。

### 完整图鉴与漫游

完整图鉴在目录中打开，入口注明会显示全部合作；也可从首页搜索或示例起点直接开始一次漫游。它保留全网选人、点线看作品与来源、沿边前往；点所在歌手的相邻唱片即前往，其他唱片只选中。选中非邻居艺人时显示「和 TA 隔几首？」，开一局新寻声。

漫游条固定在底部：「返回上一位」「回到起点」、当前路线、「本次发现 · N 首」、「结束探索」。已结束的漫游只能选中，不能走动，条上换成「已结束」章、停下时的路线、「回顾 · N 首」与「继续本次探索」。回顾纸页按 PRD v0.2 顺序排版：日期、起点、途经与留下的概览 → 默认展开的留下的歌（附发现来源）→ 可折叠的「我走过的路」（返回后换方向另起一段，不画不存在的连线）→ 可折叠的「途经艺人」，每位带「从 TA 再出发」→ 「保存发现卡片」与后续动作「继续本次探索 / 开始新探索 / 回到小院」。

桌面可拖动、滚轮缩放，也提供 44px 的缩放按钮与适配全图；触摸输入按同一平移与缩放模型实现；真机双指尚未验证（只有模拟视口）。这是平移与缩放的纸桌，不是 PRD v0.2 设想的拖动旋转。WebGL 不可用时，用相同数据、位置与可见性绘制二维图：背面唱片是不可聚焦的灰色纸圆加「？」，SVG 只画已翻开的边。HTML 控件、纸角、墨线和留白继续沿用店内的纸件材料，不增加常驻讲解面板。

### 手机唱片桌的名字

唱片多、屏幕小时，名字按需要排序，而不是按唱片先后：

- 必需的名字先放：所在歌手、终点、选中的歌手、所在歌手的相邻歌手。背面朝上的唱片永远不显示名字。
- 必需的名字先试唱片下、上、两侧与四角；放不下时沿印刷引线外移（最远约 125px），仍放不下再换顺序重排，最多重试 3 次。所在歌手的名字只短距离外移，否则压在自己的唱片上。
- 其余名字只在有空位时显示，不压住任何需要名字的唱片；拥挤时可以压在较安静的唱片上。
- 名字标签不盖住界面纸件，也不互相重叠；持有键盘焦点的标签保持原位。连线上的歌名优先给刚翻开的合作。

重复静态几何由 `sakura-batch.js` 按材质、阴影和操作分组实例化；唱片和呼吸部件保留独立变换。场景跨 hash 路由保留，销毁时释放几何、材质、纹理、后处理目标、renderer 和监听。空闲 30fps / 转场 60fps 是调度目标，不代表实体手机已达标。

## 分享卡片

战绩卡和发现卡片都在本机 canvas 上绘制，尺寸 1080×1350（4:5 竖图；未在微信朋友圈或小红书实际发布检查），不上传。两张卡共用一套夜场票根语言：

- 背景：夜空靛紫渐变、唱片纹路的同心圆、两段串灯与光斑、花瓣；顶部是三瓣品牌标、Music Map 字标与樱粉眉行。
- 票面：暖纸票根，两侧真实的缺口，虚线撕线把票面与存根分开；右上是鼠尾草绿双圈、带樱花与日期的圆形印章（「抵达」「揭晓」或「发现」）。
- 唱片：认识的歌手用 TA 在唱片桌上的颜色画正面封套；没翻开或不该透露的一律画牛皮纸背面，中间一个「？」。
- 字体：歌手名与歌名用衬线字，过长时在同一字体内缩小，不换成无衬线；说明文字用无衬线。
- 页脚：短网址与一行樱粉衬线字「每条连线都是一首真实的合唱录音」。

**寻声战绩卡**：眉行「寻声 · 两位歌手之间，隔着几首歌？」。票面写起点与终点的名字，中间一排是走过的站，全部背面朝上（站数过多时用「+N」合并）；揭晓而未走到时，终点前留一段虚线与「未走到」。存根写「我走了 N 步」、是否抵达与提示次数，右侧是题目链接的二维码，旁注「扫码走同一道题 · 只带起点和终点」。战绩卡不印中间歌手的名字和任何歌名。

**发现卡片**（PRD v0.2 §5.8）：眉行「发现卡片 · 从喜欢，走向未知」。票面写「从 <起点> 出发」、途经人数、留下首数与日期，一排按遇见先后排列的歌手封套，沿合唱走过去的用「→」相连，中途退回再换方向的用「↩」；排下方一行图例说明所用记号（「按遇见的先后 · →：沿合唱走过去」，有「↩」时加「↩：退回后换个方向」）。「↩」和图例里的「↩：退回后换个方向」在 `b5939d9` 加入并已上线；更早的 `0b1eadc` 在同一位置用「·」，图例只说明「→」。超过 6 位时只画前 3 位与后 2 位，中间写「··· 另 N 位」，并贴「节选 · 共 N 位」签；存根列留下的歌，最多 5 首，更多时写「等 N 首」并贴「节选 · 共 N 首」签；没有留下时写明“这次还没有留下歌曲”。节选必须标出，不把截断的路线当作完整路线。

预览是居中的暖纸 dialog，宽度不超过 440px（手机左右留 12px），图片占主体，显示「PNG · 1080 × 1350」；按钮为「下载图片」「关闭」，浏览器支持文件分享时才出现「分享图片」，触屏另提示“也可以长按图片保存”。只有用户点击才下载或分享；关闭、下一次预览或离页时释放图片。预览不参与全局位移动画。

## 上游来源与适配

实际复用 [Sakura Crossing](https://github.com/Kenton-GMI/sakura-crossing) 的 MIT 渲染代码，固定提交 `de01898e89c7f6ab3fad93fa802f0f5ac66fbd81`：

| 模块 | 采用范围与本地改动 |
| --- | --- |
| `toon.js` | cel 分层明暗、彩色阴影；为独立场景创建并释放材质和色阶纹理池，适配 Three 0.186.1 shader |
| `post.js` | 深度墨线、调色和 FXAA；同步投影类型与裁切参数，控制像素预算与小场景线宽 |
| `palette.js` | 采用原调色板，文件未修改 |

Three 使用 **0.186.1**；小院建筑、雨篷、唱片关系桌、樱树、程序纹理和构图由本项目编写，没有复制上游完整街区、人物、纹理原图或音频。文件哈希、修改说明与固定来源见 [SOURCE.json](../web/js/vendor/sakura/SOURCE.json)，完整许可见[第三方说明](../THIRD_PARTY_NOTICES.md)。0.15 的夜场与 0.16 的唱片店改造都没有修改 `web/js/vendor/sakura/` 下的文件，天空、灯光、调色与墨线取值都在本项目的 `sakura-scene.js` / `sakura-world.js` 中。

GSAP 使用 [Standard No Charge 许可](https://gsap.com/community/standard-license/)；0.16 起不再使用 Flip 插件。界面滚动沿用 OverlayScrollbars MIT 实现，参考取舍见[界面研究](../references/research/2026-09-27/interface-restraint.md)。分享卡片的二维码使用 qrcode-generator 2.0.4（MIT）。

`themes.js` 沿用文件名，只管理樱花场景；`themes.css` 保留纸面 token 与浅色业务样式。旧 `festival` / `zine` 运行选择和 PNG 绘制已退出，历史偏好键 `music-map-visual-theme:v1` 不再读写或监听，不主动清除业务数据。
