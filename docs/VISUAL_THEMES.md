# 樱下放映 · 夜场 · 视觉规范

2026-09-27 · MVP **0.15.0** / 产品文档 **2.6**。本文沿用原文件路径，记录当前唯一的樱花艺术方向；完成证据见[项目状态](PROJECT_STATUS.md)，业务规则见[产品方案](../product/docs/01-product-plan.md)。

## 艺术方向

用户于 2026-09-27 明确：“优秀的视觉包装是我们项目能否成功的根本”。0.15 把「樱下放映」从晴天午后改为傍晚到夜场演出，并将「樱下放映 · 夜场」冻结为最终美术方向。后续只做打磨，不再换方向。

同一个三渲二音乐小院，在散场前后的夜里连接现场照片、唱片与共同纪念。界面沿用小院里的物件：音乐关系放在唱片桌上，场次成为票签，照片放进托盘，收藏收进纪念册。

主色为：夜空靛紫（theme-color `#23214a`）与地平线暖辉、串灯琥珀、暖纸、樱粉和鼠尾草绿。夜空上的文字用奶油色，导航与右上按钮用深色玻璃；纸件是带夜间灯光阴影的暖纸，焦点环为琥珀色。清楚的中文、作者署名和原始照片占据操作层。WebGL 不可用（`body.spatial-fallback`）时，外壳回到浅纸深字。

构图变化度 / 动态强度 / 视觉密度采用 **(7, 4, 3)**，范围 1–10，只表达设计取舍，不是质量评分或设备性能指标。

| 部位 | 当前表达 |
| --- | --- |
| 首页 | 夜场小院上的首屏：眉行「音乐现场 · 散场以后」、大字「同一刻，／另一面。」、承诺句「用另一位观众的视角，补完整你记住的那一晚。」与三步「交换现场照片｜双方同意｜两人署名的双联票根」；回访用户不显示三步。下方是个人纸卡，首访副行写「照片默认私藏，双方同意才交换」。首页不显示照片投影标签，只保留一处标题 |
| 外壳 | 顶部品牌加一套空间导航，取消重复入口和外观选择；首页隐藏地点名和右上邀请码按钮，其他页面的地点名为玻璃条；没有 hash 时固定进入首页 |
| 探索 | 唱片店默认一局寻声：题签问「A → B，隔着几首歌？」，唱片背面朝上，底部是手牌；完整网络收在目录的「完整图鉴」 |
| 现场 | 场次票签、照片托盘与可展开目录；待回应有单独入口，换房和离开留在“本场”菜单 |
| 制卡 | 工作纸上选照片、留一句；更多细节折叠，可见范围与保存动作清楚；同页重开继续未保存草稿 |
| 收藏 | 纪念册承载本人现场、音乐、路线和示例；分类为轻量下划线标签，筛选为胶囊。双联空态可回已有现场，身份失效提供重新入场 |
| 结果 | 全屏夜场仪式页展示两位作者的双联，主按钮「保存双联图片」；PNG 为夜场票根 |

说明放在用户需要决定的位置。保留私藏／展示、指定两卡、双方同意、作品来源、示例标记与实际错误，不用段落解释可见的按钮。长内容正常滚动，不裁掉表单或保存操作。页面沿用 OverlayScrollbars 2.16.0 自动隐藏细浮动条，弹窗保留原生滚动。

### 共同的界面材料

- **暖纸与细墨线**：封套、票签、工作纸、纪念册共用纸色、边线、纸角和夜间灯光阴影，避免每页另起一套卡片组件外观。连线歌单与双联票根共用票条、打孔边和虚线中缝。
- **可读的中文**：正文不小于 14px，辅助文字不小于 12px；0.15 清理了原先 9–11px 的小字。温度章和印章用文字字形表达，不只靠颜色。
- **物件与索引**：唱片可点、照片可翻；分类和路线使用短索引。查看署名、输入内容与确认同意使用清楚的 HTML 控件，不把长文字烘焙进模型。
- **操作有位置**：艺人入口跟随唱片投影，作品内页从探索打开，制卡工作纸对应工作桌。物件、投影标签和底部索引调用同一业务动作。
- **主次与留白**：场景承载探索和照片，细节按需展开。待回应、错误、可见范围和保存操作保持可见，装饰不覆盖点击区域。

## 空间与动作

`#sakura-world` 保留同一 Three 场景，导航与实物点击复用相同操作。手机独立机位，HTML 层承担表单、署名、同意与错误反馈。

| 机位 | 空间位置 | 操作 |
| --- | --- | --- |
| `home` | 小院、开放店面与树下舞台 | 本人卡进入收藏，工作桌记录现场，独立示例入口 |
| `explore` | 唱片店内的音乐关系桌，由桌灯照亮 | 寻声：翻开、前往、提示、揭晓、连线歌单；完整图鉴：选人、点线看作品、和 TA 隔几首；拖动、缩放与适配全图 |
| `live` | 照片墙 | 可见现场卡、申请与回应 |
| `editor` | 工作桌近景 | 两步制卡，决定私藏或展示后保存 |
| `records` | 店内收藏架 | 私人卡片、双联、音乐与路线 |
| `photo` | 选中照片抬起 | 预览并继续编辑、申请或打开双联 |

GSAP 3.15.0 驱动镜头和抬卡；连续选择从当前位置接续，中断旧动画。关闭弹窗回基础机位，替换弹窗不抢镜头。减少动态时直接显示目标。唱片慢转、花瓣与猫的呼吸保持轻量，动作不自动保存、公开或同意交换。

夜场光照集中在 `sakura-scene.js` 的 `NIGHT` 常量和 `sakura-world.js` 的材质中：
- 天空是世界固定的靛紫渐变，地平线有暖辉。
- 月光是唯一投影的光。另有店内暖光、左右两组串灯的点光与 17 个灯泡光晕、舞台 par 灯与光束，以及亮窗远屋和自发光夜樱。
- 灯的数量在运行期固定，机位切换只补间强度，不触发重新编译；收藏机位另把店内暖光移到右侧吊灯下。
- 唱片桌在 `explore` 机位由 `tableSpot` 照亮。
- 首次挂载且没有减少动态偏好时，场景先暗两帧，再在不超过 1.4 秒内逐组亮灯；减少动态时灯光直接到位。
- 光晕与光束不参与拾取。调色与墨线参数由本项目设定，手机暗角降低。

0.14 起用纸件的实际占位共同构图：测量可见面板、菜单和弹窗，按唱片桌、照片墙、工作桌或收藏架的几何边界适配剩余区域。透明容器不挡点击；展开、收合、窗口缩放后重新取景。标签与实体共享可见区域，名字之间避碰，轻微移位时用短线指回唱片。极短屏收起重复标题与数量，保留可操作的文字大小。

手机弹窗使用下方工作纸，暂时收起不可操作的导航；短屏表单整张滚动，隐私、错误和末尾动作可达。

### 唱片桌与寻声

唱片桌的确定性布局按数据集与关系类型缓存，寻声与完整图鉴使用同一组位置，选择或翻开都不重排。真实精选的 12 位艺人、13 条边构成两个独立回路；真实共唱与示例风格连接保持区别。场景排布只服务构图，不表示音乐相似度、地理位置或算法评分。

进入唱片店默认一局寻声，画面由以下几部分组成：
- 左上是题签：小标「寻声 · 真实合作精选」，大字问题，状态行写步数、认识与翻开数量。用过提示 ① 后，题签加「还隔 N 首」和温度章。
- 右上最多三个主控件：提示、换一组、目录。其余入口收进目录：自选起终点、放弃并揭晓、完整图鉴、数据集切换与记录。
- 桌面上，起点有光圈，终点有「终点」签。未认识的唱片是纸背封套加「？」，不带名字、颜色或数量；桌上只画已翻开的合作。
- 底部手牌列出所在歌手的全部合作。未翻开的只写歌名；翻开时卡片翻面，桌上唱片翻正，墨线从当前歌手生长到对方。
- 提示 ② 在对应手牌贴「试试这张」签，桌上从当前唱片画一段带箭头的铅笔残段，不能点。短屏手机（高 ≤ 640）隐藏提示便签、手牌收成单行，提示改在按钮里写「翻开 · 试试这张」。
- 手机竖屏在高 > 1.9×宽时使用竖向机位。

抵达时整桌按与终点的距离依次翻面，路线逐段描成金色，再打开「连线歌单」。揭晓时，用虚线墨画出本专题的一条最短路线，用户自己的路线保持实线。连线歌单是竖排 setlist：唱片封套与歌名票条交替，票条带打孔边，写版本与来源，可展开署名，带「留下」「带到现场」。注脚写明“最短”只指本专题收录范围。仪式可跳过；减少动态时直接显示终态并打开歌单。WebGL 不可用时，播放约 1.8 秒、可跳过的二维仪式。

答案在翻开、提示或揭晓之前不出现：搜索、各面板、二维 DOM、读屏文字、三维封面和投影标签都只读同一可见集合。局中关闭署名表，因为署名会出现尚未认识的艺人名；抵达或揭晓后在歌单中开放。

完整图鉴在目录中打开，入口注明会显示全部合作。它保留全网选人、点线看作品与来源、沿边前往与策展标签；页头显示「你已亲手翻开 m/13 首合作」。选中非邻居艺人时显示「和 TA 隔几首？」，开一局新寻声，替代原「找关联」与最短链高亮。

桌面可拖动、滚轮缩放，也提供 44px 的缩放按钮与适配全图；触摸输入按同一平移与缩放模型实现，真机双指结果以项目状态为准。WebGL 不可用时，用相同数据、位置与可见性绘制二维图：背面唱片是不可聚焦的灰色纸圆加「？」，SVG 只画已翻开的边。HTML 控件、纸角、墨线和留白继续沿用照片墙及纪念册的材料，不增加常驻讲解面板。

重复静态几何由 `sakura-batch.js` 按材质、阴影和操作分组实例化；照片、唱片和呼吸部件保留独立变换。场景跨 hash 路由保留，销毁时释放几何、材质、纹理、后处理目标、renderer 和监听。空闲 30fps / 转场 60fps 是调度目标，不代表实体手机已达标。

## 照片与业务边界

- 真实照片保持原内容，不做动漫化、补景或换人；页面和票根只改变外框与排版，作者、文字、活动与快照不变。
- 场景最多发布 6 张当前有权读取的卡。首页可显示本人私卡，同伴仅显示已展示的卡；缺本人卡的 seed 明示示例。
- 联网贴图取既有 bearer 接口授权的 blob，不把 `photoId` 拼成公共 URL。退出、撤权或清缓存前先撤下模型贴图，再释放 blob。
- 申请、拒绝、取消和完成画面由实际状态驱动，动画不伪造结果。私藏默认、指定接收者与双方同意继续适用。
- 当前没有内置音频或已核实的 QQ 音乐直达，图形不标作真实频谱或播放器。

## 双联仪式页与 PNG

已接受的交换与已保存的双联进入全屏夜场仪式页，三个入口共用这一页：真实房间接受后、收藏页翻开、本地示例接受后。页面组成：
- 夜空与串灯下，写「A × B」衬线大字、场次与日期。
- 左右各一张照片，下面是各自作者与短句；中缝为虚线。
- 存根写共同线索：两卡同歌时写歌名，否则写同一时刻，再否则写场次。
- 「双方同意」印章带日期。

当前浏览器第一次看到某个交换时完整首映：两半照片从两侧带倾角合拢，中缝闪光、花瓣散开，存根自上展开，印章落下，最后按钮出现。再次打开为简短回看；减少动态时直接显示终态；点击或按键可跳过。主按钮「保存双联图片」，次按钮「返回现场」（本地回看为「返回示例现场」）；其余为弱链接，删除最弱。只有真实已接受或已保存的交换才出现这一页。短屏手机缩小照片，只把两枚按钮固定在底部，保证首屏能看到整张票根与存根。

PNG 为 1600×1800 的夜场票根，与页面共用虚线中缝、存根与印章。双联印两位作者、「AI 生成示例照片」标签与「双方已同意共同署名」；本地情景的页脚写明角色、现场与歌曲为虚构。单卡为「我的现场卡」版式，印章为「我的现场」。双联取接受时的两卡快照，单卡取本人的当前卡；生成与下载不改变房间或交换状态。

原生 dialog 展示真实 PNG，图片占主体；桌面宽度不超过 460px，手机保留边距与长按保存。提供“下载图片”“关闭预览”，浏览器支持文件分享才显示“分享图片”，用户点击后触发。预览不参与全局位移动画；关闭、下一次导出或离页释放对象 URL。

## 上游来源与适配

实际复用 [Sakura Crossing](https://github.com/Kenton-GMI/sakura-crossing) 的 MIT 渲染代码，固定提交 `de01898e89c7f6ab3fad93fa802f0f5ac66fbd81`：

| 模块 | 采用范围与本地改动 |
| --- | --- |
| `toon.js` | cel 分层明暗、彩色阴影；为独立场景创建并释放材质和色阶纹理池，适配 Three 0.186.1 shader |
| `post.js` | 深度墨线、调色和 FXAA；同步投影类型与裁切参数，控制像素预算与小场景线宽 |
| `palette.js` | 采用原调色板，文件未修改 |

Three 使用 **0.186.1**；小院建筑、雨篷、唱片关系桌、樱树、程序纹理和构图由本项目编写，没有复制上游完整街区、人物、纹理原图或音频。文件哈希、修改说明与固定来源见 [SOURCE.json](../web/js/vendor/sakura/SOURCE.json)，完整许可见[第三方说明](../THIRD_PARTY_NOTICES.md)。0.15 的夜场没有修改 `web/js/vendor/sakura/` 下的文件，天空、灯光、调色与墨线取值都在本项目的 `sakura-scene.js` / `sakura-world.js` 中。

GSAP / Flip 使用 [Standard No Charge 许可](https://gsap.com/community/standard-license/)。界面滚动沿用 OverlayScrollbars MIT 实现，参考取舍见[界面研究](../references/research/2026-09-27/interface-restraint.md)。

`themes.js` 沿用文件名，只管理樱花场景；`themes.css` 保留纸面 token 与浅色业务样式。旧 `festival` / `zine` 运行选择和 PNG 绘制已退出，历史偏好键 `music-map-visual-theme:v1` 不再读写或监听，不主动清除业务数据。
