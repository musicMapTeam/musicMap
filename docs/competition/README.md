## 1. 报名介绍（240字，提交前由团队核对）

演出散场后，你拍到了舞台，却错过了人海里的合唱。Music Map × Space 帮同场观众交换彼此没有的视角：用自己的照片、时刻与一句话制作现场卡，先私藏或导出；愿意分享时，按共同瞬间发现另一张卡，发出具体的双卡申请。对方独立同意后，双方得到保留作者与原话的双联纪念票。产品支持自定义场次、扫码邀请与真实独立会话；Map 提供有来源的合作作品和官方听歌外链，作为可选音乐发现入口。采用音乐节排版与纸质票根视觉，使用 AI 辅助设计、开发和示例图制作；不把规则匹配称为模型推理。

参赛方向：**赛道2 · 创新音乐产品**。名称保留 Music Map × Music Space，核心主张是“同一刻，另一面”。采用Space为主叙事、Map为可选音乐入口；不要求评委强行从地图走到一场虚构活动。

上述是完整服务介绍，单文件情景版不能声称支持跨设备房间或联网照片。身份、真实分工、参赛前已有部分与赛期新增部分由团队核对；不代填报名身份或推断上线历史。研究与取舍见[竞争力复盘](../../references/research/2026-09-27/README.md)。

## 2. 两分钟现场演示脚本

先让评委看见“为什么想要另一面”，再展示申请和同意。素材若来自AI生成图片，持续说明是演示用图。本轮同一浏览器的两个来源分别保存独立身份，不属于实体双手机或外部用户研究。下表为现场讲解节奏；已交付的106秒操作录屏剪点以交付清单为准。

| 时间 | 实际操作 | 讲清什么 |
| --- | --- | --- |
| 00–12秒 | 双联成品与两位作者；一句场景问题 | “你拍下舞台，有人记住人海；散场后，想把另一面也带回去。” |
| 12–32秒 | A创建自定义场次，选择自己的照片、返场、舞台视角，保存私卡并可导出 | 一个人已经有纪念收益；上传不自动展示 |
| 32–50秒 | 展示邀请二维码／邀请码；独立会话B加入，选人海视角并主动展示 | 同场小圈的入场方式；用户自填场次并非到场认证 |
| 50–70秒 | A看到“同样记得返场，舞台和人海”的解释，确认具体两张卡，发出申请 | 推荐理由来自填写的字段；交换是提出共同署名邀请，不是解锁照片 |
| 70–90秒 | 切B独立查看并接受；回A看到同意结果 | 发起者不能代替对方同意；拒绝也可结束申请 |
| 90–104秒 | 展示双方自动保存、下载双联PNG；作者、原话与场次一致 | 可带走的共同产物；后续改卡不改旧快照 |
| 104–116秒 | 真实Map沿一条合作作品前进，打开来源／官方听歌入口 | 音乐发现有真实收获；不是虚构曲库，也不是站内播放器 |
| 116–120秒 | 产品名、AI使用与访问说明 | 主张、已实现范围、尚未部署／未开展真实试用如实说明 |

真实录屏可剪掉等待，但不得用截图或接口直接改状态来替代未发生的界面操作；A/B切换需标清楚。录制素材、成片时长与来源统一记在交付清单。

### 三个评委问题的直接回答

- **为什么不用相册或群聊？** 想收齐照片时，相册更直接。这里提供的是一次指定对象、对方回应、共同署名的纪念体验；是否值得多一步，需要真实观众试用来判断。
- **为什么需要陌生人？** 并非前提。先从同行朋友与活动小圈进入，另一位置／注意点提供不同视角；不宣称已经解决全城匹配或长期社交。
- **AI在哪里？** AI辅助研究、设计、代码与示例图制作；合作边有来源，视角排序是可解释规则，没有实时推荐模型或AI契合度分数。

AI 使用说明按实际制作填写：当前已用 AI 辅助方案梳理、界面与代码实现、生成虚构现场图；团队负责产品取舍、内容筛选和实际检查。模板排版、规则匹配、SQL 查询不是模型推理，未使用的工具或模型不列作成果。
