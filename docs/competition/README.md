# Music Map × Music Space · 初赛材料工作稿

更新：**2026-09-27** · 应用 **MVP 0.2.0** · 赛道：**创新音乐产品**。这份文件是报名和录制工作稿，尚未提交。产品规则见[产品方案](../../product/docs/01-product-plan.md)，部署与素材边界见[交付方案](../../product/docs/02-delivery-plan.md)。

## 1. 报名介绍（100—300 字）

> Music Map × Music Space 面向喜欢探索音乐、也想在演出中自然认识同好的人。Map 把艺人与作品关系变成可探索的地图；Space 让观众用一张现场图、一首歌或一个环节和一句话做卡，因共同的音乐时刻看见彼此。双方各自确认后，交换不同视角，自动留下双联记忆，并可导出票根继续收藏。原型采用独立匿名会话与邀请码房间，也保留单机情景演示。我们用动态排版与音乐节视觉呈现“同一场，两种故事”，借助 AI 完成设计与开发；当前场次、图片和音乐数据均明确标为演示，未接入音频。

此段与当前已实操的联网核心能力一致；若最终只交静态情景演示，应删去“独立匿名会话”，把“自动留下”改为“手动保存”；静态版本也支持导出票根。队员姓名、真实分工、参赛前已有部分与赛期新增部分由团队核对，不在此处代填或推断上线历史。

## 2. 2 分钟现场演示脚本

主线：**发现一首歌 → 进入同场 → 两张卡相遇 → 接收者同意 → 留下双联记忆**。以最终运行页面录制；联网段使用两个独立浏览器会话或两台设备，持续标明 A / B。两张照片、示例音乐和场次标识保持可见，不伪装真实演出数据。

| 时间 | 画面与操作 | 旁白 / 字幕要点 |
|---|---|---|
| 0:00—0:12 | 双联画面特写；两张图从各自视角进入构图，大字“同一场，两种故事” | “你记住舞台，我记住人海。同一场演出，留下了不同的记忆。怎样把共同喜欢变成自然的交流理由？” |
| 0:12—0:30 | Map 选起点、沿一条关系切中心、展开作品依据；保留示例数据标识 | “从喜欢的声音出发，沿作品关系继续发现。Map 给每次探索一个可理解的方向，也把你带到相关的现场。” |
| 0:30—0:50 | 进入 Space 真实房间；A 建房，选舞台图、共同曲目 / 环节、写短句并展示 | “在 Space，先做自己的现场卡。选择留住哪个瞬间，再决定是否让这个房间的人看见。” |
| 0:50—1:10 | 切到独立会话 B，输入同一邀请码，选人海图、制卡并展示；看见 A 的卡 | “朋友用邀请码加入。同一首歌、同一个返场，是开口的理由。两张卡讲的可以是完全不同的故事。” |
| 1:10—1:30 | A 指定 B 的卡，确认两卡快照，发出；画面明确 pending；B 打开申请并接受 | “这次只交换眼前两张卡。发起者不能代替对方同意，接收者始终可以拒绝。” |
| 1:30—1:48 | 双联完成画面；两端显示同次结果与自动保存的个人记录；下载并打开 PNG 票根 | “对方接受后，两种视角成为共同记忆，自动保存在各自记录里，也能带走一张双联票根。” |
| 1:48—2:00 | 从音乐回到 Map；收尾显示产品名、AI 制作说明和实际完成边界 | “沿音乐发现彼此，把另一种视角带回去。当前演示使用虚构场次与素材，尚未接入真实音频。” |

若联网流程未完成实操或评审部署受阻，录制明确标注的本地角色版：A / B 是示例角色，接受后展示**手动保存**，不使用“真实同步”“自动保存双方记录”等解说。剪辑可以压缩等待，但不能拼接不存在的状态变化。旁白可独立录制，不需商业歌曲作背景音乐。
