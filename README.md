# Music Map × Music Space

**同一刻，另一面。散场以后，用另一位观众的视角，补完整你记住的那一晚。**

当前版本 MVP **0.7.0** · 产品文档 **1.8** · 2026-09-27

首页可直接「做一张卡」或「邀请朋友」。0.7 将樱花主题做成常驻三维音乐小院：切换导航，镜头移动到唱片台、照片墙或收藏架。音乐探索增加逐人制作署名与独立开放曲库；保留「声浪现场」「樱下放映」「独立刊物」三套外观。

![Music Map × Music Space · 0.4 版本封面](delivery/cover.png)

## 现在能做什么

- **音乐探索**：11 位艺人、10 首作品、10 条有来源的共同演唱关系；点击作品查看每个人的演唱、词曲、制作等已核实工种。地图顶部可搜索 120 首独立开放曲库作品，数据中的共同署名与人工核实制作名单分开。虚构图谱和旧记录保留。
- **本地情景演示**：首页「做一张卡」进入本地制卡，也可点选照片卡进入换卡；切换 Lin / 阿遥，完成展示、申请、接受、拒绝与取消。接受后自动收好两人的双联记忆。
- **自己的音乐现场**：填写场次、可选日期／地点／歌名，上传一张自己的照片，选一个时刻和视角；默认私藏，一个人也能导出纪念卡。
- **真实同场交换**：独立匿名身份、邀请码／二维码、主动展示的卡墙；用共同瞬间和不同视角说明相遇理由。申请指向两张确定的卡，由接收者本人同意。
- **可带走的记忆**：交换后生成双联票根，可保存PNG。记录页按现场记忆 / 音乐探索浏览；后续改卡不会改写已完成的交换，各自删除自己的记录。
- **可切换的完整外观**：夜场照片、三渲二街角、独立音乐刊物三种方向；主题覆盖探索、制卡、交换、记录与 PNG，业务内容保持一致。

**真实合作有来源；本应用没有内置音频，试听链接已撤下，QQ 音乐同版本直达尚未核实。** 署名来源仍可单独查看。本地情景和旧房间仍是虚构场次，预置图由AI生成。新房间使用参与者自行填写的活动与选择的照片，不验证到场。现有实操是内部独立会话，不代表已有外部用户或公网服务。

先服务散场后的同场小圈，共同纪念是交换收益，音乐探索是可选入口。依据见[竞争力复盘](references/research/2026-09-27/README.md)。

## 三种外观，同一段音乐记忆

从**右上角主题按钮**选择，按钮显示当前主题名。默认是「声浪现场」，浏览器会独立记住外观选择；切换不重置探索路线、房间身份、草稿或交换记录。

| 外观 | 艺术方向 |
| --- | --- |
| **声浪现场** `festival` · 默认 | 深墨、海沫绿与现场照片；叠放照片卡、彩色唱片、轻悬浮控件 |
| **樱下放映** `sakura` | 暖白、樱粉与彩色阴影；同一个三维音乐小院，通过镜头进入不同功能，使用 Sakura Crossing 的 MIT 三渲二管线 |
| **独立刊物** `zine` | 暖纸、油墨与酸绿；不对称照片卡和唱片封套，保留轻量操作层 |

每套外观沿用对应的单卡与双联 PNG 排版，用户照片和记录内容保持原样。樱花主题使用 Three 0.186.1 的真实透视场景与 GSAP 3.15.0 曲线镜头，跨路由保留场景；切走主题才释放资源。三套主题的卡片与弹窗使用 GSAP / Flip，减少动态偏好显示静态结果。查看[视觉规范](docs/VISUAL_THEMES.md)和[来源许可](THIRD_PARTY_NOTICES.md)；实际检查按版本记录在[项目状态](docs/PROJECT_STATUS.md)。

## 已下载的开放数据

Hugging Face 的 `maharshipandya/spotify-tracks-dataset` 完整 CSV 已下载到 `data/external/spotify-tracks-dataset/dataset.csv`：**114,000 行、20,118,244 B**，固定 revision `635b034f69257814eff850a5c2b3346fe458134f`。没有下载音频或模型权重。

前端仅内置整理后的 120 首共同署名作品，原 CSV 不进入页面或运行包。复现命令：`python scripts/datasets/download_hf_catalogue.py`。范围与来源见[下载记录](references/research/2026-09-27/huggingface-download.md)，10 首人工核实作品见[逐人署名记录](references/research/2026-09-27/collaboration-roles.md)。

## 快速运行

需要 **Node.js 24 或更新版本**。

```sh
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:8787/**。同一个服务提供页面与 SQLite 交换接口，无需外部数据库或模型。

开发前端：`npm run dev`；真实房间开发时另开终端运行 `npm run server`。Vite 将 `/api/live` 转发到本机 `8787` 端口。

### 两种交付

| 交付 | 能力 | 条件 |
| --- | --- | --- |
| `dist/index.html` 单文件 | 完整 Map 与本地双角色情景演示 | 浏览器；可评估 WorkBuddy 等 HTML 托管 |
| Node 完整版本 | 上述功能 + 真实房间交换 | Node.js 24、同源服务与持久化磁盘；对外部署使用 HTTPS |

`npm run preview` 只预览静态页面。静态托管不能运行 SQLite 后端。`npm start` 默认仅监听本机，支持 `HOST`、`PORT`、`DATA_DIR`；完整部署和 Docker 命令见[实施规格](product/docs/03-build-guide.md)。数据库默认在 `data/music-map.sqlite`，已排除 Git，不得打进分享包。

每次推送，GitHub Actions 构建 **music-map-space-demo**（单文件）与 **music-map-space-runtime**（页面、后端、运行说明）两份产物，保留 14 天。见 [Actions](https://github.com/musicMapTeam/musicMap/actions/workflows/build.yml)。仓库同步与网站部署分别记录。

## 两分钟体验

### 一个人快速看完整流程

首页点「做一张卡」→ 保存本地示例卡 → 申请交换 → 切到阿遥接受 → 打开双联记忆，下载票根。首页已选中的照片卡也可再次点击进入示例。Map 从桌面左侧或手机底部导航进入。

### 两个人真实交换

首页点「邀请朋友」→ 创建或加入同场 → 填写场次并分享邀请 → 双方各自制卡，接收方展示 → 发起方确认两卡并申请 → 接收方在自己的浏览器同意。

同一台电脑可用两个浏览器或普通 / 无痕窗口。朋友的手机需要已部署的链接，或同一网络下可访问的服务地址；`127.0.0.1` 不能发给另一台设备。身份保存在浏览器，清除站点数据会失去身份访问能力，MVP 暂无账号找回。
